# 鉤子執行排序

多個擴充功能可以註冊同一個事件鉤子，例如訊息生成前與訊息生成後。鉤子執行排序用於指定這些擴充功能的執行順序。

## 為什麼需要排序

### 擴充功能之間的依賴關係

多個擴充功能監聽同一個事件時，執行順序決定最終結果。例如：

- 翻譯擴充功能處理使用者輸入，內容過濾擴充功能檢查結果：翻譯在過濾之前執行。
- 提示詞格式化擴充功能與上下文擴充功能同時執行：格式化在新增上下文之後執行。
- [記憶圖](/zh-TW/features/memory-graph)在[多 Agent 編排](/zh-TW/features/orchestrator/)之前完成記憶檢索。

### 第三方擴充功能相容

第三方擴充功能同樣出現在排序清單中，可與內建擴充功能一起調整順序。

## 上下移動排序介面

鉤子執行排序在擴充功能面板中依事件類型分組展示，每個擴充功能有上移與下移按鈕，清單頂部的擴充功能先執行：

![Hook 順序面板](/images/hook-order/hook-order-panel.png)

```d2
direction: right

EVT: "generation_after_world_info_scan 觸發"
H1: "memory-graph 完成記憶檢索" {
  style.fill: "#e1f5ff"
}
H2: "search-tools 寫入搜尋結果到世界書" {
  style.fill: "#fff3e0"
}
NEXT: "繼續下一階段"

EVT -> H1 -> H2 -> NEXT
```

上圖對應面板中「世界書掃描後」事件的排序：記憶圖排在搜尋外掛之前，因此記憶檢索先執行，搜尋結果隨後寫入。本輪的記憶檢索讀不到搜尋外掛當輪寫入的世界書條目；若要讓它參與本輪檢索，把搜尋外掛移到記憶圖之前。

## 排序介面元素

- **事件分組** —— 每個事件（如 `generation_before_world_info_scan`、`generation_after_world_info_scan`）獨立維護一份排序，互不影響
- **上移 / 下移** —— 調整該事件下擴充功能的執行順序
- **重置為偵測到的順序** —— 按程式碼掃描到的註冊順序恢復

## 儲存

排序儲存在設定中，重新啟動後依上次設定恢復。

## 相關功能

- [記憶圖](/zh-TW/features/memory-graph) —— 記憶檢索的時機受鉤子順序影響
