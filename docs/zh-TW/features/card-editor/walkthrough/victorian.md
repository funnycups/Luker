# 用 Studio 製作一張接入記憶圖與多 Agent 編排的角色卡

本頁用一張偵探角色卡演示 CardApp Studio 的完整開發流程：從一句題材描述開始，讓 Studio 建立記憶圖節點類型、設定多 Agent 編排、編寫角色卡專用世界書，最後製作隨案情更新的 CardApp 面板。

四個子系統在同一張卡上分工：記憶圖保存長期記憶，多 Agent 編排準備每次回覆，世界書提供背景與規則，CardApp 顯示狀態。

## 最終結果

成品是一張名為「維多利亞案宗」的偵探題材角色卡。<code v-pre>{{char}}</code> 是 1888 年倫敦的福爾摩斯式獨立顧問，你扮演一位委託人（或蘇格蘭場來訪的探長）提交案宗，與他一起調查案件。

這張卡同時接入以下子系統：

- **記憶圖** —— 為案件建立嫌疑人、線索、取證地點、證人四類節點。AI 在回覆後提取案件資訊，建構並連接不同的記憶節點；下一回合召回時，相關記錄自動進入上下文。
- **多 Agent 編排** —— 每次回覆前由一組 agent 準備寫作材料：整理最近對話的狀態、規劃這一回合要推進的內容、審查草稿是否遺漏線索、供述是否矛盾、時代細節是否出錯，最後合成一段編排結果交給主模型。
- **角色卡專用世界書** —— 收錄維多利亞倫敦背景、偵探辦案規矩和一個記錄案件狀態的條目。
- **「當前案宗」CardApp 面板** —— 顯示案件名、當前階段、嫌疑人和線索，隨案情推進更新。

整個搭建過程不需要編寫程式碼，只需用自然語言描述需求。Studio 會自行提出方案、編寫檔案、建立世界書，並把各項內容關聯到這張卡。

## 前置條件

- 一個可用的 Luker 執行個體
- 已設定完成的 LLM API，推薦使用 Claude、GPT-5 等支援工具呼叫的模型。Studio 依靠模型主動呼叫工具來修改角色卡，模型不具備該能力時無法運作
- 在擴充功能面板中為角色卡編輯助手選擇「模型請求 LLM 預設」與「模型請求 API 預設」，Studio 的 AI 呼叫由這兩項指定

## 1. 建立空白角色卡並進入 Studio

開啟右側角色管理面板，點擊「新建角色」，名稱填寫「維多利亞案宗」，描述、第一條訊息和世界書繫結全部留空，交給 Studio 填寫。

接下來開啟「擴充功能」面板 → 展開「角色卡編輯助手」→ 點擊 **「&lt;/&gt; CardApp Studio」**：

![Studio 入口](/images/walkthrough/victorian/step-01-studio-entry.png)

::: tip Studio 也適用於未啟用 CardApp 的角色卡
「角色卡編輯助手」對沒有 CardApp 的角色卡使用[普通彈窗](/zh-TW/features/card-editor/popup)，包含 CardApp 的角色卡使用 Studio。Studio 按鈕可以主動把任何卡引入 Studio，功能完整，涵蓋記憶圖節點類型、多 Agent 編排覆寫、正則指令碼、世界書和角色卡內容；普通彈窗只支援修改角色卡內容和世界書條目。
:::

## 2. 描述題材，由 Studio 提出方案

點擊 Studio 左欄輸入框，描述想要的效果，具體實作交給模型：

```
我要從零做一張維多利亞時代倫敦的偵探角色卡。

- 主角是 1888 年倫敦的獨立顧問，我扮演委託人提交案宗，和他一起查案。
- 希望 AI 記住案件裡的嫌疑人、線索、取證地點和證人，聊到相關人物時能想起來。
- 每次回覆先起草，再檢查線索有沒有遺漏、嫌疑人的說法有沒有矛盾、時代細節有沒有出錯，然後改寫定稿。
- 世界書收錄維多利亞倫敦背景和偵探辦案規矩。
- 做一個「當前案宗」面板，顯示案件名、階段、嫌疑人和線索，隨對話更新。

請按合適的順序完成。每一步先把方案告訴我，我確認後再寫。
```

![輸入題材需求](/images/walkthrough/victorian/step-02-first-prompt.png)

發送後，Studio 不會直接開始編寫，而是先說明整體方案。

## 3. Studio 提議記憶圖結構

Studio 先說明記憶部分：它會在記憶圖裡為這張卡增加嫌疑人、線索、取證地點、證人四類節點，並列出每類節點記錄的欄位，例如嫌疑人記錄動機、不在場證明和可疑程度，線索記錄發現地點和關聯嫌疑人。

它也會說明這些節點如何連接：線索指向關聯嫌疑人，取證地點指向在那裡發現的線索。召回時，記憶圖沿著這些關係找出與當前場景相關的記錄。

它還說明了為什麼不單獨記錄受害者和推理結論：這兩類資訊數量少、變化快，放在案件簡介和對話裡更合適，單獨建立節點會讓記憶結構臃腫。

::: tip 記憶圖的預設類型和自訂類型
記憶圖預設只有事件這一種核心類型，用來記錄時間線。角色卡可以按題材增加自己的節點類型和欄位，讓 AI 在提取記憶時按固定結構歸檔。偵探卡需要的「嫌疑人」「線索」就屬於這類自訂類型。詳見 [記憶圖](/zh-TW/features/memory-graph)。
:::

## 4. Studio 提議多 Agent 編排

接下來是生成部分：它建議使用 Loop 模式。每次回覆前，一個 agent 在同一會話裡反覆呼叫工具，讀最近聊天、查世界書、查記憶圖，判斷資訊是否足夠；資訊足夠後，它寫出一段編排結果，交給主模型寫成正文。

這種模式適合偵查題材：查案需要先確認現場、證人和時間線，再決定下一步，固定流程無法預先寫死。代價是每次回覆多一輪模型呼叫，換來更穩定的推理。

編排器還提供其他模式：Spec 用固定的階段和節點組成流程，Agenda 由規劃 agent 動態調度，Director 由主代理直接創作正文。記憶圖和世界書在這些模式裡同樣可用。

## 5. 確認後，Studio 一次完成全部內容

確認方案後，Studio 開始批次修改：

![Studio 寫入全部內容](/images/walkthrough/victorian/step-05-tool-calls.png)

一輪中它完成了：

- 在記憶圖裡增加嫌疑人、線索、取證地點、證人四類節點，僅對這張卡生效，不影響全域設定
- 設定 Loop 編排，寫入系統提示詞和工具開關，同樣只對這張卡生效
- 建立角色卡專用世界書，寫入維多利亞倫敦背景、偵探辦案規矩、案件狀態條目、蘇格蘭場文化和白教堂區背景
- 編寫角色描述、性格、開場白和場景，並把世界書關聯到這張卡

每項修改都會彈出對話框顯示改動內容，確認後才會寫入。可以逐條批准，也可以一次全部批准。

::: tip 案件狀態條目如何驅動面板
世界書裡有一個條目專門記錄案件當前狀態。條目中同時寫著當前狀態和更新規則：AI 每次生成前讀到它，回覆時按規則把新進展寫回變數，CardApp 面板讀取變數重新整理顯示。詳見[逐樓層變數](/zh-TW/features/variable-op-log)。
:::

::: tip 正則指令碼同樣可以管理
Studio 也能編寫和修改正則指令碼，例如移除思考標籤或轉換顯示格式。
:::

## 6. 製作案宗面板

最後一步發送：

```
繼續。現在做最後一步：「當前案宗」面板。
顯示案件名、階段、嫌疑人、線索和取證地點，每條回覆生成後更新一次。
風格用維多利亞霧都氛圍：暗色羊皮紙、襯線字體、暗紅和暗黃邊框。
樣式、配色和取值細節你定。
```

Studio 會寫出面板，並接入案件狀態。

## 7. 端到端測試

退出 Studio，正常發送角色扮演訊息。向 <code v-pre>{{char}}</code> 提交一份倫敦白教堂的案宗：

> "偵探，白教堂有人深夜被害，死在自家閣樓上。死者是 35 歲的私塾教師莫妮卡·惠勒，丈夫亨利·惠勒報的案。我剛從蘇格蘭場調檔過來，請您接手。"

### a. 聊天回覆

![端到端聊天回覆](/images/walkthrough/victorian/step-07a-chat-reply.png)

這條回覆能看出兩層約束在起作用：世界書條目規定了時代背景和辦案規矩，編排結果給出了這一回合的推理方向。主模型負責把這些材料寫成對話，不再自行決定查案的節奏。

### b. 查看編排過程

開啟聊天區旁的**執行面板**（窄屏下從底部抽屜拉起），其中列出這個 agent 每一輪的思考、呼叫的工具與回傳結果：

![多 Agent 編排執行面板](/images/walkthrough/victorian/step-07b-stage-output.png)

某一輪查錯世界書、遺漏記憶或資訊不足就提前結束時，可以在這裡定位。編排失敗時（API 設定錯誤、逾時等），面板標出失敗點，本輪改用普通生成。

### c. 查看記憶圖

在擴充功能面板中開啟 Memory 一節 →「查看圖」，其中列出當前對話累積的節點與關係：

![記憶圖檢視](/images/walkthrough/victorian/step-07c-memory-graph.png)

圖中有嫌疑人、線索、取證地點、證人和事件，連線表示它們之間的關係。回覆生成後，記憶圖會提取這一輪出現的案件資訊；下一回合召回時，相關記錄會自動進入上下文。下次聊到亨利·惠勒時，他的供述和關聯線索會一起被找到。

## 8. 面板隨聊天更新

繼續對話。AI 會在回覆中更新案件狀態，面板隨之重新整理：

![CardApp 面板第二輪後：嫌疑人、線索、取證地點逐條顯示](/images/walkthrough/victorian/step-06b-cardapp-turn2.png)

## 提示詞要點

有效的需求描述說明目標與期望效果，具體實作交給 Studio。

1. **說明題材與效果**
   - 示例：「維多利亞倫敦偵探卡，需要記憶圖的案件節點類型、多 Agent 編排、角色卡專用世界書和隨對話更新的面板」。
   - 結構細節由 Studio 提出，例如記憶類型應包含哪些欄位。

2. **先審閱結構提案**
   - Studio 先給出結構方案，確認後寫入。
   - 需要調整時直接說明，例如「證人與嫌疑人合併」，或「改由規劃 Agent 決定先查哪條線索」。

3. **讓 Studio 解釋取捨**
   - 示例：「為什麼受害人不單獨記錄？」
   - Studio 會說明這類資訊變化快，放在案件簡介與世界書條目中更穩定。
