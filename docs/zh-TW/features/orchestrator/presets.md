# 編排預設

編排模式（Spec、Agenda、Loop、Director）在全域與角色卡作用域各維護一份預設庫。預設保存該模式編排面板裡的全部內容：系統提示詞、工具開關、子代理、規劃設定、執行上限和編排結果注入策略。提示詞預設和 API 連線只按名稱引用，執行時才解析。

本頁說明預設欄的操作、兩種作用域的區別，以及預設之間如何引用。

- **全域** —— 預設存放在擴充設定裡，對所有聊天可用。
- **角色卡** —— 預設存放在角色卡本身，匯出角色卡時一併匯出。

::: tip 為什麼按模式分庫
各模式的預設結構不同，所以分庫儲存。切換執行模式時顯示當前模式的庫。
:::

## 預設欄

預設欄位於每種模式編輯面板的頂部：

![預設欄 —— director 模式](/images/orchestrator-presets/01-director-default.png)

它提供了一組標準操作：

- **下拉選單** —— 列出當前模式與作用域下的全部預設。選中一項後，編輯器載入該預設的內容。
- **新建** —— 使用當前模式的出廠預設資料建立一份新預設。
- **複製** —— 複製當前啟用預設並指定新名稱，副本成為新的啟用預設。
- **重新命名** —— 修改名稱。引用該預設的設定繼續有效。
- **刪除** —— 刪除該預設。如果刪除的是當前啟用預設，列表中的下一份會自動成為啟用預設。如果整個庫被刪空，下一次讀取時會用出廠資料重新填充 `Default`。
- **匯入 / 匯出** —— 使用標準的可移植 JSON 格式。匯入時會讓你起個名字，加進當前庫；匯出會把當前啟用預設寫到磁碟。

在面板中進行的編輯會寫回**當前啟用**預設，無需顯式儲存；關閉面板或切換預設時，當前狀態已經持久化。

## 全域作用域 vs 角色卡作用域

沒有載入角色卡時，預設欄展示該模式的全域庫。在這裡改動會影響所有未使用角色卡預設的聊天。

載入了角色卡後，下拉分成 **角色卡** 和 **全域** 兩組，其中一組處於選中狀態。該選中項決定使用哪個庫：

- **選中角色卡預設** —— 卡上的預設對這個角色生效；這次聊天裡全域啟用預設被忽略。
- **選中全域預設** —— 這次聊天以全域啟用預設為準。卡自己的庫原樣保留在卡上，隨時可以從同一個下拉切回卡上的任何預設。

切換組會立即寫入卡的啟用槽位並隨卡持久化，所以這個選擇會跟著卡一起匯出 / 匯入。

如果這張卡還沒有自己的預設庫，角色卡組是空的。在選中卡預設的狀態下儲存一次編輯，卡的預設庫就建立起來。

::: info 角色卡匯出時帶上自己的預設庫
匯出角色卡時會把卡自己的預設庫一併打包，因此在另一臺機器匯入這張卡時，卡上的預設也會一併匯入。
:::

## 編排預設和提示詞預設、API 預設的關係

編排預設是一次生成裡相互獨立的層之一，另外兩個是 SillyTavern 的提示詞預設和連接設定：

| 概念 | 控制什麼 | 存在哪裡 |
|---|---|---|
| 編排預設 | 子代理、工具、規劃 Agent、Loop 上限、系統提示詞、編排結果注入 | 擴充設定或角色卡上 |
| 提示詞預設 | token 預算、取樣器、提示詞順序、越獄 | SillyTavern 預設 |
| API 預設 | 端點、模型、API 金鑰 | API 連線設定 |

編排預設按**名稱**引用提示詞預設和 API 連線。例如一份 Director 預設可以把評審子代理指定為強模型預設，其餘子代理使用快速預設。切換編排預設只更換編排層；提示詞預設和連線設定保持不變。

名為 `審訊節奏` 和 `重敘事密度` 的兩份預設，可以共用同一份提示詞預設和連接設定，只在編排形態上有差別：不同的子代理、不同的規劃 Agent 指令、不同的注入深度。在預設欄中切換即可生效。

## Agent 提示詞預設解析優先讀角色卡

當一份編排預設按名字把某個 agent 指定為某份提示詞預設（`Sonnet · 慢節奏評審`、`Haiku · 快速` 等）時，這個名字在生成時才解析。查找順序：

1. 當前角色的卡內嵌預設集合：只要卡上有一份內嵌預設的名字命中，直接使用它。
2. 你本地的聊天補全預設庫。
3. 前兩者均未命中時，回退到編排器設定中指定的全域執行時預設。

卡優先的順序在角色卡攜帶自己推薦預設時很關鍵：編排設定和它引用的預設一起分發，接收方無需單獨匯入匹配的預設。同名時，卡上的副本在該角色範圍內優先。

載入角色卡後，編排器抽屜裡每個 agent 的預設選擇器頂部會顯示「本卡內嵌」分組，列出卡上的內嵌預設，可與本地預設一併選擇。

## 把編排設定提交到角色卡時按需內嵌引用的預設

向當前角色卡提交編排設定時，Luker 會先預檢 agent 引用的提示詞預設名稱，查出哪些還沒內嵌到卡上。這裡的「提交」既包括編排器抽屜裡的「儲存到角色卡預設」，也包括「AI 迭代工作台」彈窗裡的「套用到角色卡」——這些入口共用同一次預檢。

若有未內嵌的引用，會彈出彙總視窗列出它們，提供以下動作：

- **全部內嵌** —— 把每個引用預設的本地內容複製到角色卡，使編排設定在匯出後可以完整執行。
- **僅儲存名稱** —— 按原樣保存編排設定，不嵌入預設內容。接收方若沒有同名本地預設，相關 agent 會使用執行時預設回退。
- **取消**——中止提交。

彈窗只在提交時出現。

角色卡槽位如何管理、編輯、剝離連線欄位，詳見[角色卡繫結預設與人設](/zh-TW/improvements/card-bound-presets)。

## `Default` 預設

`Default` 是普通預設，可以重新命名、編輯、刪除。

刪光一個庫裡的預設後，下次讀取時 `Default` 會從出廠資料重新生成。想恢復出廠設定，刪除全部預設即可。

## 用法舉例

預設欄支撐的幾種常見用法：

- **同一張卡用多份預設** —— 日常場景使用一份回應快、成本低的預設，重要場景使用一份速度較慢、密度更高的預設。均儲存在角色卡作用域下，需要時從下拉中選擇。
- **把角色卡預設提升為全域** —— 把卡上的啟用預設匯出，再把預設欄切到全域作用域，匯入這份 JSON。全域庫中也會包含同一份預設，對所有聊天可用。
- **試一份預設但不承諾** —— 複製一份當前啟用預設，在副本上修改。如果實驗未成功，從下拉中切回原版即可恢復。
- **把調好的編排和角色卡一起交付** —— 在角色卡作用域中調整預設，確認下拉中選中的是卡上的預設，然後匯出角色卡。匯入後即可獲得同一套編排。
