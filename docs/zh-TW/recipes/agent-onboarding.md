# 多 Agent 入門：預設、記憶圖、網路搜尋

::: tip 這篇文件解決什麼問題
Luker 的[多 Agent 編排](/zh-TW/features/orchestrator/)、[記憶圖](/zh-TW/features/memory-graph)、[搜尋外掛](/zh-TW/features/search-tools)各自獨立可用，但要讓它們協同形成一套完整流程——由 Agent 團隊抽取記憶、檢索同人設定、構思劇情走向、起草正文——需要按順序完成一系列配置。

這篇從一份空白配置出發，逐步引導你完成預設、Director、記憶與搜尋的設定，不假設你已經看過上述深入文件。完成後你將獲得一份可用的預設配置，之後隨時可以在**工作台 → AI 迭代**裡繼續調整。
:::

## 你會得到什麼

完成本文配置後，在主對話傳送一則訊息，**主模型 不會立刻開始寫作**——Agent 團隊會先執行一輪編排：

- **記憶偵察 Agent** 掃描記憶圖，檢索與當前劇情相關的角色 / 事件 / 地點
- **設定考據 Agent**（必要時）聯網檢索當前題材的同人設定
- **劇情構思 Agent** 從多個不同角度並行起草劇情結構草圖，由主 Agent 從中選擇
- **主 Agent** 根據前序 Agent 的產出直接完成正文寫作
- **記憶整理 Agent** 在起草完成後將本回合新出現的事實寫回記憶圖

記憶圖的**自動抽取 / 自動壓縮**完全交由 Agent 處理，搜尋引擎預設使用 DuckDuckGo，不需要 API Key 與嵌入設定。

## 整體分工結構

```d2
direction: down

start: "你發一條訊息" { shape: oval }

orch: "Director 主 Agent 接管" {
  style.fill: "#e1f5ff"
  scouts: "起草前偵察\n記憶偵察 Agent · 聊天偵察 Agent ·\n世界書偵察 Agent · 設定考據 Agent(必要時聯網)"
  brain: "中段頭腦風暴\n劇情構思 Agent\n按多角度並行出劇情草圖"
  draft: "主 Agent 起草正文"
  curate: "起草後清理\n記憶整理 Agent 把新事實寫回記憶圖"
}

end: "正文直接顯示在聊天裡\n(主模型 本回合不參與)" { shape: oval }

start -> orch.scouts -> orch.brain -> orch.draft -> orch.curate -> end
```

記憶圖自身的自動抽取與自動壓縮保持關閉，由 Agent 團隊接管記憶整理。搜尋功能啟用後，設定考據 Agent 才能執行聯網檢索，否則回傳零結果。

## 你需要先有什麼

- 可正常運行的 Luker 實例，主對話能夠正常生成回覆
- 一份可用的 [RP 預設](/zh-TW/basics/presets)，最好已經配置好文風、越獄、NSFW 指導

## Step 1 —— 選擇起始預設

任何日常使用的 RP 預設均可。本步驟僅確認你有一份可用的寫作預設作為起點——下一步將在此基礎上派生 Director 所需的預設。

## Step 2 —— 配置預設助手，派生 Director 要用的預設

Luker 的外掛呼叫 LLM 大致分為**不同類別**，需要的預設形態完全不同：一類是**外掛產出 RP 內容**的場景，例如 Director 的 Agent 團隊起草正文與評審子 Agent 複審，需要帶越獄 / 文風 / 反八股的完整 RP 預設；另一類是驅動**工作台 AI 迭代**與 **CardApp Studio** 的迭代 AI，涵蓋預設設定檔、記憶圖配置、記憶圖內容、編排、角色卡與世界書，它們透過工具呼叫修改設定或抽取結構化資料，不寫故事——任何混入的 RP 指令均會干擾模型執行外掛指令，所以這些位置需要一份**只保留越獄**的精簡預設。

Director 這條流程同時涉及這些類別：

| 路徑 | 給誰用 | 預設形態 |
|---|---|---|
| **Agent 路徑** —— 主 Agent + 子 Agent 起草正文 | 實際負責撰寫內容的 Agent，產出直接進入聊天介面 | 一份調好可用於 tool calling 的 RP 預設：保留越獄 / 文風 / 反八股，移除與編排器衝突的佔位符和硬格式限制 |
| **迭代 AI 路徑** —— 在**工作台 → AI 迭代**中調整設定時由迭代 AI 使用 | 一個透過工具修改設定的編輯器，完全不創作正文 | 一份**只保留越獄**的精簡預設——沒有文風指導、沒有 NSFW 寫作規則、沒有任何敘事元指令 |

::: tip 為什麼不同路徑不能共用一份預設
RP 預設預設假設「主模型獨立完成整個回覆」，將其放入 Agent 工具迴圈後會出現以下問題：

- 與 Agent 的系統提示詞爭奪注意力
- 把「必須輸出 schema」「強制思維鏈」這類格式約束強加進起草環節，破壞 tool calling
- 讓佔位符（角色卡描述、人設、世界書條目）被編排器主路徑**重複注入**

工作台 AI 迭代對此更為敏感——它完全不寫故事，只透過工具呼叫修改設定與方案。任何混入的 RP 指令均會干擾模型執行外掛指令。
:::

### 2a —— 設定工作台的預設 AI 與 `plugin-only` 預設

工作台內的預設編輯同樣由 LLM 驅動，因此先在工作台設定好共用的連線設定與生成預設：

1. 開啟**工作台**（快速鍵 `Alt+W`、魔杖選單 → **工作台**或右下角入口），切換到左側底部的**設定**。
2. 在**共用**中選擇一個可正常運作的連線設定。
3. 在**生成預設**中選擇已匯入的示例，或點擊**匯入示例**安裝內建的 `plugin-only`。點擊**從現有預設派生**會開啟預設工作台並選取**僅保留破限**模式。

![工作台設定 —— 共用 AI 連線與生成預設](/images/recipes/agent-onboarding/step-02a-workbench-settings.png)

工作台裡的全部迭代目標，包括記憶圖配置、記憶圖內容、編排、預設、角色卡與世界書，預設跟隨共用配置，也可以在單獨指定中覆寫；**目前來源**欄位顯示每項配置的取值層級。

### 2b —— 用預設迭代派生 **Agent 路徑** 的預設

切換到**工作台 → AI 迭代 → 預設設定檔**（也可以點聊天補全預設工具列上的魔杖按鈕，或**擴充功能 → 聊天補全預設助手 → 在工作台中開啟**）。將頂部的**編輯模式**切換為「**編排器適配**」，然後傳送：

> 幫我把這個預設改成 Agent 專用預設

![多智能體編排適配模式下的預設助手](/images/recipes/agent-onboarding/step-02-preset-assistant.png)

它預設會**派生一份新預設**（原名加 `-orchestrator` 後綴）——原預設保持不動。它會自動執行以下操作：

- 關閉會與編排器主路徑**重複注入**的佔位符：角色卡描述 / 人設 / 範例對話 / 顯式世界書拼接
- 把會干擾 tool calling 的強格式約束（強制 schema、固定思維鏈頭）從硬要求改寫成弱引導
- 將僅在最終成稿中生效的指令（summary、風格收束等）條件化到「最終提交訊息」階段
- **保留**聊天歷史、文風指令、越獄 / 反八股指令——主 Agent 起草與評審子 Agent 均會讀取

在**改動清單**中逐條審閱 diff 並套用即可。

::: tip 可在同一會話中繼續改造預設
「編排器適配」只是**編輯模式**之一。將**編輯模式**切回預設的「**通用編輯**」並新增對話，即成為通用預設編輯器，例如可以讓它「新增一個反八股指導並補充反面範例」「把文風指導從濃墨重彩改為克制細膩」「合併幾條意思重複的規則」。詳見[預設助手](/zh-TW/features/preset-assistant)。

「編排器適配」過程還會**主動掃描預設中可重用的文風 / 格式 / 寫作紀律規則**，作為候選提案擷取為 Skills（原文照搬、綁定當前預設作用域、在原位置補充一行指標）。提案均可獨立審閱。詳見[把預設裡的文風 / 輸出格式抽成 Skills](/zh-TW/features/preset-assistant#在編排器適配模式下抽取-skills)。
:::

## Step 3 —— 切換到 Director 模式並設定預設

切換到**工作台 → 編排**：

1. 開啟**啟用編排**，在頂列模式選擇器中選為**導演**（Director）。
2. 開啟**編排 → 設定**，將**預設 API 和提示詞預設**裡的連線設定與生成預設設為 Step 2b 派生的 `-orchestrator` 預設。
3. 在**迭代**區域確認迭代 AI 使用 `plugin-only` 預設（或留空以跟隨工作台預設設定）。

## Step 4 —— 將記憶圖的抽取與召回交給 Agent

切換到**工作台 → 記憶圖 → 設定**：

- **啟用** ✓ 保持開啟
- **自動抽取** ✗ 關閉（交給 Agent 團隊裡負責整理記憶的子 Agent）
- **自動壓縮** ✗ 關閉（Agent 收尾時一併處理）
- **啟用記憶召回注入** ✗ 關閉（Agent 團隊會在起草前自行執行一輪召回）

![記憶設定：抽取、壓縮、召回都交給 Agent](/images/recipes/agent-onboarding/step-04-memory-toggles.png)

::: info 想完全使用「記憶圖內建的抽取、召回和壓縮」
預設 Director 設定將抽取 / 召回 / 壓縮納入自身職責。如果你更信任記憶圖內建的鏈路（已經設定好多模型路由、Hybrid + Rerank 等），則：

1. 將**自動抽取**、**自動壓縮**、**啟用記憶召回注入**重新啟用
2. 在 [Step 6 的編排 AI 迭代](#step-6) 裡告訴 AI：「我不想讓 Agent 管理記憶，自己用內建的記憶圖就夠了」
3. 在**改動清單**中逐條審閱並套用即可
:::

## Step 5 —— 選一個搜尋引擎

開啟**擴充功能 → 搜尋工具**，**搜尋提供方**預設是 `DuckDuckGo（無需登入）`——保持預設即可。如需更換引擎，從下拉中選擇其他提供方，例如自架的 `SearXNG（自訂實例）` 或任一需要 API Key 的提供方。

![搜尋引擎選擇](/images/recipes/agent-onboarding/step-05-search-provider.png)

::: info 頂部開關跟這個流程的關係
**將工具暴露給主模型** 和 **在請求前執行搜尋 Agent** 是搜尋外掛**相互獨立**的工作模式，與 Director 無關——本流程透過 Director 的搜尋子 Agent 執行搜尋，這些開關均**無需啟用**。

如果不使用 Director 也需要搜尋能力，請參閱[搜尋外掛](/zh-TW/features/search-tools)的「工作模式」。
:::

## Step 6 —— 在工作台 AI 迭代中客製編排 {#step-6}

開啟**工作台 → AI 迭代 → 編排**（或在**編排**工作區頂列點 **AI** 按鈕），這是後續所有自訂的入口。

![AI 迭代 —— 編排](/images/recipes/agent-onboarding/step-06-iter-studio-director.png)

在頂部的**改哪一份**切換編輯作用域：

- **全域** → 編輯**全域**預設方案，所有未做覆寫的角色卡均繼承該方案
- **角色單獨的** → 編輯**這張卡的專屬方案**，僅對該卡生效，並隨卡匯出 / 匯入

::: tip 在角色卡上調出的優秀編排可以提升為全域
如果為某張卡迭代出一套特別合用的 Director 方案，可以在**工作台 → 編排 → 準備階段**點擊**儲存到全域**（或匯出 JSON 後在全域作用域匯入）。記憶結構同理。
:::

### 全域作用域：可使用的指令

- 「我不想讓 Agent 管理記憶，請去掉負責抽取和召回的 Agent」
- 「我不想讓 Agent 聯網搜尋同人設定，請去掉負責搜尋的 Agent」
- 「讀取世界書裡的圖像生成指導，加一個子 Agent，在正文起草完成後構思插畫的插入位置和提示詞」
- 「讀取世界書裡的變數更新指導，加一個子 Agent，在正文起草完成後構思變數如何更新」

### 角色卡作用域：可使用的指令

- 「結合這張卡的世界觀和當前劇情，給主 Agent 加一段專門的寫作紀律」
- 「這張卡有自訂的體力 / 心情變數，負責整理記憶的子 Agent 抽取時優先填這幾個欄位」
- 任何與當前角色卡題材強相關、不適合放入全域配置的指令

在**改動清單**中逐條審閱並套用即可。如果結果與預期不符，可在**改動記錄**中復原，或在**編排 → 準備階段**重設回預設 Director 方案。

## 可選步驟 —— 讓 AI 設定記憶結構

記憶圖結構同樣可以由 AI 修改。切換到**工作台 → AI 迭代 → 記憶圖配置**；需要修復目前聊天裡的節點時，選擇**記憶圖內容**。

![記憶結構 AI 迭代](/images/recipes/agent-onboarding/step-07-schema-studio.png)

記憶結構同樣區分**全域**與**角色單獨的**作用域，角色卡上的結構隨卡匯出。可以針對題材客製，例如：

- 修仙題材：給角色加「修為境界」「靈脈」欄位
- 政治題材：新增「派系」節點類型，記錄派系關係和敵對圖
- 生存題材：新增「物品」節點，追蹤道具的耐久、狀態

## 實際執行

返回主對話傳送一則訊息，即可在**執行面板**懸浮窗中即時看到 Agent 團隊的執行過程：

![Director 一回合內 Agent 團隊的產出](/images/orchestrator/director-takeover/director-real-final-body.png)

- **起草前偵察**：各自給出 `Item / Source / Why`，列出與當前劇情相關的角色、事件、世界書條目
- **中段頭腦風暴**：從多個角度並行起草劇情結構草圖，供主 Agent 選擇
- **起草後評審**：子 Agent 對主 Agent 的草稿提出評審意見，由主 Agent 決定採納哪些修改
- **收尾整理**：把這一回合新出現的事實寫回記憶圖

在**執行面板**懸浮窗展開任意助手列（或點擊**檢視執行詳情**跳轉到**工作台 → 編排 → 執行**），即可檢視模型思考與每次工具呼叫的入參與回傳。

如果結果不滿意，在執行面板點擊**結果不滿意？AI 診斷**，即可帶入這次執行的軌跡回到[編排 AI 迭代](/zh-TW/features/orchestrator/iteration-studio)繼續修改。
