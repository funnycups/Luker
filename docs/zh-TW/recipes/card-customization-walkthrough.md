# 給一張角色卡做專屬編排

本頁示範如何把一張有嚴格輸出格式的角色卡改造成專屬編排：從一句需求產生工作流，用模擬找出 AI 八股並據此改進提示詞與 Skills，再讓工作台寫一個格式校驗工具。

整個過程由 AI 迭代工作台完成。範例使用一張社群中「輸出格式嚴格、變數更新繁瑣」的同人卡，方法適用於所有帶格式硬要求或專屬設定的角色卡。

---

## 用一段需求定制專屬編排

匯入角色卡並選中後，從「擴展 → 多 Agent 編排」打開面板，點擊 **打開編排編輯器**。

![編排編輯器打開後](/images/recipes-card-customization/01-editor-opened.png)

頂部第一欄標明當前角色卡、所用的執行模式，以及當前編輯的是「全域」還是「角色卡覆蓋」配置。本次工作目標是**角色卡覆蓋**——所有改動只作用於這張卡，不會污染其它卡。

右上角點擊 **打開 AI 迭代工作台**。

![工作台剛打開](/images/recipes-card-customization/02-studio-fresh.png)

工作台左側為對話區，右側即時呈現當前編排的流水線（主代理與全部子代理）。我們在輸入框寫下一句話：

> 請給本角色卡定制一個專屬編排，把全域的預設配置改成更貼合這張卡的版本。

![輸入框裡寫好定制請求](/images/recipes-card-customization/03-prompt-typed.png)

點擊 **發送**。工作台讀取角色卡內容與世界書，列出當前可見的 Skills，隨後開始改寫主代理提示詞、新增對這張卡有意義的子代理、調整可見 Skills 集合。改動會彈出一張變更審閱卡片，綠色為新增，紅色為刪除；審閱後點擊 **應用到角色卡覆蓋** 即寫入。

![一次變更審閱卡](/images/recipes-card-customization/04-review-card.png)

如果需要細看，可在卡片內展開「逐行差異」；如果不想閱讀程式碼，卡片頂部的一句話會指明修改了哪個欄位。

::: tip 提示
若不願意逐條手動審閱，可在輸入框下方勾選 **自動套用變更**。下一節「標註八股並改進」在自動套用模式下會更順暢。
:::

數輪迭代後，工作台會用一段話總結改動內容與改動貼合這張卡的理由。

![工作台執行完成，AI 總結](/images/recipes-card-customization/05-customize-summary.png)

至此，這張角色卡獲得專屬編排，下次給它發送訊息時即採用該配置。

---

## 執行模擬，標註八股，讓工作台改進

定制完成並不代表結束，AI 寫出的提示詞仍可能重複自身的慣用表達。在中文角色扮演圈中，這類套話通稱為「八股」。其中最常見的一種是**序數與量詞構成的「計數體」**：

- 動作拆分：將一個連貫動作分成可數的細段，如「一寸一寸往回縫」、「鑽了半寸又停住」；
- 節奏拍數：把聲音或呼吸量化為拍子，如「三下，停半拍，又三下」；
- 程度量化：用「一點」、「半分」之類模糊數詞代替真正的感受動詞，如「忽然弱了一點」、「弱了半分」。

孤立出現一次沒有問題，但一段敘述反覆使用同類計數結構後，文本會退化為 AI 分鏡報告——讀者聽見的是計數，而不是「有人在經歷這一刻」。

工作台提供 **模擬** 功能：在不真正向聊天寫入訊息的前提下，讓當前編排執行完整流程並展示產出。我們用它來檢測八股。

::: tip 提示
模擬繼承當前聊天的全部上下文：已發生的對話記錄、當前啟用的世界書與 Skills、當前的預設與連線配置。模擬呈現的是「如果此刻在這張卡上發送一條訊息會得到什麼」，而不是脫離上下文的執行。如果想更換上下文測試，先在主介面切換聊天或調整世界書，再回到工作台。
:::

回到工作台輸入框：

> 請用「我坐起身」作為使用者輸入，執行一次模擬，並展示給我審閱。

工作台調用模擬工具，執行一輪完整的主代理與所有子代理。Director 模式執行全套流程需要幾分鐘，請耐心等待。模擬結束後彈出 **模擬回顧** 視窗：

![模擬回顧彈窗：主代理輸出與各子代理追蹤](/images/recipes-card-customization/06-sim-baseline.png)

模擬回顧視窗預設展開各段落，向下滾動即可看到主代理最終回覆全文。我們瀏覽這段文本，選出「AI 腔調」較重的短語。

點擊 **批註模式**——切到開啟後，**在產出文字裡用滑鼠選中**任意一段，所選區域自動呈黃色高亮，旁側出現批註輸入框。在批註框內簡述不滿意之處即可（一兩個字通常足夠）。

![本輪模擬標註了一處量詞計數八股](/images/recipes-card-customization/07-sim-baseline-annotated.png)

本輪基線中選擇了一處作為示例：

| 選中的片段 | 批註 |
|---|---|
| 「連閃了五下」（頭頂警報燈的反覆閃爍） | 「五下」將視覺變化轉換為次數，「光閃 → 數次數」是將感官事件抽象為資料點的典型 |

標註完成後點擊視窗底部 **提交並繼續**。工作台將這條批註視為「症狀」回饋給 AI：AI 看到的不是孤立的不滿意短語，而是帶上下文位置的問題清單，可以據此反推根因。常見情況下，根因不在某個子代理寫得不夠細，而在於一條共性規律尚未被任何提示詞承接。

![工作台根據批註做根因診斷](/images/recipes-card-customization/08-improvement-thread.png)

本次迭代中，工作台把這條批註歸入「量詞計數八股」一類：將真實的體感、動作、時間、身體拆解為「數字 + 量詞」的可計數刻度。它沒有立即修改，而是先與使用者確認：該規則是絕對禁律，還是需要保留例外？在使用者明確「無例外」後，工作台讀取審稿子代理實際載入的 Skill，而不是名稱最接近的另一個，將規則寫入該子代理在執行時真正會讀取的位置，並把原句作為反例寫入其中，附以「獨立禁律、字面命中即記錄、與上下文是否溫暖、詩化、物理寫實或口語自然無關」的明文。這樣下一輪模擬時，審稿子代理才會真正檢測到此類違例。

::: warning 重要
工作台不會在主代理提示詞中加入「不要說 X」這類字面禁令，這種逐處修補無法解決根本問題。它會尋找觸發八股的根本原因（哪個子代理審稿寫得過於粗略、哪條 Skill 缺少禁律），並從該處修復。
:::

隨後**再次執行模擬**：

> 修改完成後，再執行一次模擬，觀察序數、量詞計數體是否減少。

新彈出的回顧視窗中，先前被標註的幾條八股短語應明顯減少甚至消失。

![改進後的模擬回顧](/images/recipes-card-customization/09-sim-after.png)

將兩次回顧並排比較，差異可以直接觀察：基線中反覆出現的「光閃 → 數次數」敘述節奏（「一下，兩下，停一會兒，再三下」「閃了三下」「連閃了五下」）在改進版中基本不再出現。改進後這一輪的終稿中，量詞計數（一下、一節、一刻、一檔、幾下等）共命中 5 次，均不再出現在節奏拍點上，改用「半度」「一根管子」這類描述指代。仍有殘餘時，重複「標註—模擬」循環，通常兩到三輪即可。

## 讓工作台寫一個自訂校驗工具

這張角色卡對輸出有硬要求：回覆結尾必須附帶 `<overall>` 總覽與 `<UpdateVariable>` 變數更新兩個標籤。主代理在專注於敘事時容易遺漏這兩個標籤，導致角色卡的狀態機讀不到本輪更新，下一輪的劇情上下文也隨之失準。

針對這類需求，無需親自編寫程式碼或修改主代理提示詞，**只需用自然語言把需求告知工作台**：

> 這張角色卡的輸出格式有要求，回覆結尾必須有 `<overall>` 和 `<UpdateVariable>` 兩個標籤，不要遺漏。

![向工作台描述格式要求](/images/recipes-card-customization/11-tool-prompt.png)

工作台會自行判斷如何實作：這是一個可以由程式碼精確判定的格式檢查問題（字面比對），適合透過 **自訂工具** 解決；而被檢查與提醒補全的執行者本就是創作正文的主代理，因此工具應掛載到主代理上，由主代理在結束時調用。基於這一判斷，工作台會自動完成一組配套改動：

1. **查清執行時介面。** 工作台先核對可用的執行時介面和資料結構，必要時查閱文件，不依賴猜測。
2. **起草函式本體並試運行。** 工作台向函式本體傳入樣本參數，在沙箱中執行一次，讓執行時例外在你被請求批准之前暴露出來。
3. **寫入校驗通過的工具。** 工作台建立待審卡片；工具採用唯讀模式，內部一段 JavaScript 讀取本輪的草稿快照並檢查結尾標籤。對應的啟用開關會自動打開，下一輪主代理即可看到這個工具。
4. **修改主代理的系統提示詞。** 工作台再修改主代理的系統提示詞，追加一條規則：生成的最後一步必須調用該工具，若結果顯示缺少標籤則就地補全後再產出。

判斷哪種機制最合適、由誰調用、需要同步修改哪些位置，這些通常需要使用者提示的細節，工作台均會基於自然語言需求自行判斷，無需事先以技術語言說明。

改動仍透過審閱卡展示，綠色為新增，紅色為刪除。**由於自訂工具會在你的瀏覽器中執行 JavaScript，審閱卡帶有安全警示橫幅**：展開工具內容核對行為，確認是唯讀檢查、無副作用後再批准。無法理解的卡片應拒絕。

![新工具的程式碼審閱與安全確認](/images/recipes-card-customization/12-tool-review.png)

套用變更後，回到主代理一欄查看 **自訂工具** 列表，新工具已包含其中並預設勾選啟用。

![工具已安裝](/images/recipes-card-customization/13-tool-installed.png)

讓工作台再次執行模擬，確認主代理確實按規則調用了工具：

> 再次執行模擬驗證。

![模擬追蹤裡出現該工具的呼叫記錄](/images/recipes-card-customization/14-tool-invoked.png)

追蹤中可以看到這次工具呼叫：主代理在草稿寫到尾部之後調用該工具一次，工具返回檢查結果，主代理據此判斷是否需要補全標籤。

## 接下來

- 這一流程同樣適用於「輸出長度」「OOC 規範」「世界觀禁詞」等專屬約束：把「什麼是好」用一段話告知工作台，由它組裝編排。
- 想瞭解自訂工具在函式體內可以取得的上下文（`ctx.chat`、`ctx.characters` 等），見 [自訂工具](/zh-TW/features/orchestrator/custom-tools)。
- 想為工作台再安裝一條全域通用的 Skill，見 [用 Skills 調教角色扮演輸出](/zh-TW/recipes/rp-skills-walkthrough)。
- 若對工作台修改出的某個子代理不滿意，回到編排編輯器手動編輯即可；工作台用於提高效率，並非必經步驟。
