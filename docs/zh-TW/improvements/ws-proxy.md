# WebSocket 代理

WebSocket 代理用一條持久連線傳輸 AI 生成請求，取代每次生成都新建 HTTP 連線。它面向行動網路、跨國鏈路和會中斷長連線的網路環境，用來減少生成中途失敗。

## 解決什麼問題

傳統模式下，每次生成都是一次獨立的 HTTP 請求。網路短暫波動、行動網路切換或代理逾時都可能中斷請求，已經生成的內容隨之遺失。

WebSocket 代理在頁面與 Luker 伺服器之間建立一條長連線，所有生成請求重複使用這條連線。連線中斷後會自動重連；生成過程中斷線，重連後從斷點繼續接收內容，而不是從頭開始。

```d2
direction: down

HTTP: "傳統 HTTP：每次生成新建連線" {
  H1: "用戶端"
  H2: "伺服器"
  H3: "用戶端"
  H4: "伺服器"
  H5: "用戶端"
  H6: "伺服器"

  H1 -> H2: "建立 TCP + TLS"
  H2 -> H1: "回應後中斷" {style.stroke-dash: 3}
  H3 -> H4: "建立 TCP + TLS"
  H4 -> H3: "回應後中斷" {style.stroke-dash: 3}
  H5 -> H6: "建立 TCP + TLS"
  H6 -> H5: "回應後中斷" {style.stroke-dash: 3}
}

WS: "WebSocket 代理：持久通道" {
  W1: "用戶端"
  W2: "伺服器"

  W1 <-> W2: "建立一次連線"
  W2 <-> W1: "心跳保活 · 多個請求重複使用同一條連線" {style.stroke-dash: 3}
}
```

## 適合的場景

- 手機在 Wi-Fi 與行動網路之間切換。
- Luker 部署在遠端伺服器，透過不穩定的網路存取。
- 生成長回覆，一般 HTTP 連線容易在中途被代理或防火牆中斷。
- 企業網路會主動切斷長時間閒置的 HTTP 連線。

代理對使用者透明。Luker 會在需要時使用它，不需要額外設定。

## 可靠性機制

**心跳保活**：用戶端與伺服器定期交換心跳，避免中間設備因連線閒置而中斷。

**自動重連**：連線意外中斷後，用戶端會重新建立連線，不需要手動重新整理頁面。

**斷點續傳**：生成過程中如果連線短暫中斷，重連後從上次收到的位置繼續，內容連續且完整。

**任務清理**：長期沒有活動的生成任務會被清理，仍在持續輸出的任務不受影響。

## 安全

代理不會繞過登入、工作階段或 CSRF 檢查。建立通道時驗證目前登入狀態，後續每個請求仍然經過與一般 HTTP 相同的仲介層。連線憑證短時有效且只能使用一次，不經過 URL 傳遞。
