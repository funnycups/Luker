# 多 Agent 入门：预设、记忆图、网络搜索

::: tip 这篇文档解决什么问题
Luker 的[多 Agent 编排](/zh-CN/features/orchestrator/)、[记忆图](/zh-CN/features/memory-graph)、[搜索插件](/zh-CN/features/search-tools)各自独立可用，但要让它们协同形成一套完整流程——由 Agent 团队抽取记忆、检索同人设定、构思剧情走向、起草正文——需要按顺序完成一系列配置。

这篇从一份空白配置出发，逐步引导你完成预设、Director、记忆与搜索的配置，不假设你已经看过上述深入文档。完成后你将获得一份可用的默认配置，之后随时可以在**工作台 → AI 迭代**里继续调整。
:::

## 你会得到什么

完成本文配置后，在主对话发送一条消息，**主模型 不会立刻开始写作**——Agent 团队会先执行一轮编排：

- **记忆侦察 Agent** 扫描记忆图，检索与当前剧情相关的角色 / 事件 / 地点
- **设定考据 Agent**（必要时）联网检索当前题材的同人设定
- **剧情构思 Agent** 从多个不同角度并行起草剧情结构草图，由主 Agent 从中选择
- **主 Agent** 根据前序 Agent 的产出直接完成正文写作
- **记忆整理 Agent** 在起草完成后将本回合新出现的事实写回记忆图

记忆图的**自动抽取 / 自动压缩**完全交由 Agent 处理，搜索引擎默认使用 DuckDuckGo，不需要 API Key 与嵌入配置。

## 整体分工结构

```d2
direction: down

start: "你发一条消息" { shape: oval }

orch: "Director 主 Agent 接管" {
  style.fill: "#e1f5ff"
  scouts: "起草前侦察\n记忆侦察 Agent · 聊天侦察 Agent ·\n世界书侦察 Agent · 设定考据 Agent(必要时联网)"
  brain: "中段头脑风暴\n剧情构思 Agent\n按多角度并行出剧情草图"
  draft: "主 Agent 起草正文"
  curate: "起草后清理\n记忆整理 Agent 把新事实写回记忆图"
}

end: "正文直接显示在聊天里\n(主模型 本回合不参与)" { shape: oval }

start -> orch.scouts -> orch.brain -> orch.draft -> orch.curate -> end
```

记忆图自身的自动抽取与自动压缩保持关闭，由 Agent 团队接管记忆整理。搜索功能启用后，设定考据 Agent 才能执行联网检索，否则返回零结果。

## 你需要先有什么

- 可正常运行的 Luker 实例，主对话能够正常生成回复
- 一份可用的 [RP 预设](/zh-CN/basics/presets)，最好已经配置好文风、越狱、NSFW 指导

## Step 1 —— 选择起始预设

任何日常使用的 RP 预设均可。本步骤仅确认你有一份可用的写作预设作为起点——下一步将在此基础上派生 Director 所需的预设。

## Step 2 —— 配置预设助手，派生 Director 要用的预设

Luker 的插件调用 LLM 大致分为**不同类别**，需要的预设形态完全不同：一类是**插件产出 RP 内容**的场景，例如 Director 的 Agent 团队起草正文与评审子 Agent 复审，需要带越狱 / 文风 / 反八股的完整 RP 预设；另一类是驱动**工作台 AI 迭代**与 **CardApp Studio** 的迭代 AI，涵盖预设、记忆图配置、记忆图内容、编排、角色卡与世界书，它们通过工具调用修改配置或抽取结构化数据，不写故事——任何混入的 RP 指令均会干扰模型执行插件指令，所以这些位置需要一份**只保留越狱**的精简预设。

Director 这条流程同时涉及这些类别：

| 路径 | 给谁用 | 预设形态 |
|---|---|---|
| **Agent 路径** —— 主 Agent + 子 Agent 起草正文 | 实际负责撰写内容的 Agent，产出直接进入聊天界面 | 一份调好可用于工具调用的 RP 预设：保留越狱 / 文风 / 反八股，移除与编排器冲突的占位符和硬格式约束 |
| **迭代 AI 路径** —— 在**工作台 → AI 迭代**中调整配置时由迭代 AI 使用 | 一个通过工具修改配置的编辑器，完全不创作正文 | 一份**只保留越狱**的精简预设——没有文风指导、没有 NSFW 写作规则、没有任何叙事元指令 |

::: tip 为什么不同路径不能共用一份预设
RP 预设默认假设「主模型独立完成整个回复」，将其放入 Agent 工具循环后会出现以下问题：

- 与 Agent 的系统提示词争夺注意力
- 把「必须输出 schema」「强制思维链」这类格式约束强加进起草环节，破坏工具调用
- 让占位符（角色卡描述、人设、世界书条目）被编排器主路径**重复注入**

工作台 AI 迭代对此更为敏感——它完全不写故事，只通过工具调用修改配置与方案。任何混入的 RP 指令均会干扰模型执行插件指令。
:::

### 2a —— 配置工作台的默认 AI 与 `plugin-only` 预设

工作台内的预设编辑同样由 LLM 驱动，因此先在工作台设置好共用的连接配置与生成预设：

1. 打开**工作台**（快捷键 `Alt+W`、魔杖菜单 → **工作台**或右下角入口），切换到左侧底部的**设置**。
2. 在**共用**中选择一个可正常工作的连接配置。
3. 在**生成预设**中选择已导入的示例，或点击**导入示例**安装内置的 `plugin-only`。点击**从现有预设派生**会打开预设工作台并选中**仅保留破限**模式。

![工作台设置 —— 共用 AI 连接与生成预设](/images/recipes/agent-onboarding/step-02a-workbench-settings.png)

工作台里的全部迭代目标，包括记忆图配置、记忆图内容、编排、预设、角色卡与世界书，默认跟随共用配置，也可以在单独指定中覆写；**当前来源**列显示每项配置的取值层级。

### 2b —— 用预设迭代派生 **Agent 路径** 的预设

切换到**工作台 → AI 迭代 → 预设**（也可以点聊天补全预设工具栏上的魔杖按钮，或**扩展 → 聊天补全预设助手 → 在工作台中打开**）。将顶部的**编辑模式**切换为「**编排器适配**」，然后发送：

> 帮我把这个预设改成 Agent 专用预设

![多智能体编排适配模式下的预设助手](/images/recipes/agent-onboarding/step-02-preset-assistant.png)

它默认会**派生一份新预设**（原名加 `-orchestrator` 后缀）——原预设保持不动。它会自动执行以下操作：

- 关闭会与编排器主路径**重复注入**的占位符：角色卡描述 / 人设 / 示例对话 / 显式世界书拼接
- 把会干扰工具调用的强格式约束（强制 schema、固定思维链头）从硬要求改写成弱引导
- 将仅在最终成稿中生效的指令（summary、风格收束等）条件化到「最终提交消息」阶段
- **保留**聊天历史、文风指令、越狱 / 反八股指令——主 Agent 起草与评审子 Agent 均会读取

在**改动清单**中逐条审阅 diff 并应用即可。

::: tip 可在同一会话中继续改造预设
「编排器适配」只是**编辑模式**之一。将**编辑模式**切回默认的「**通用编辑**」并新建对话，即成为通用预设编辑器，例如可以让它「添加一个反八股指导并补充反面示例」「把文风指导从浓墨重彩改为克制细腻」「合并几条意思重复的规则」。详见[预设助手](/zh-CN/features/preset-assistant)。

「编排器适配」过程还会**主动扫描预设中可复用的文风 / 格式 / 写作纪律规则**，作为候选提案抽取为 Skills（原文照搬、绑定当前预设作用域、在原位置补充一行指针）。提案均可独立审阅。详见[把预设里的文风 / 输出格式抽成 Skills](/zh-CN/features/preset-assistant#在编排器适配模式下抽取-skills)。
:::

## Step 3 —— 切换到 Director 模式并配置预设

切换到**工作台 → 编排**：

1. 开启**启用编排**，在顶栏模式选择器中选为**导演**（Director）。
2. 打开**编排 → 设置**，将**默认 API 和提示词预设**里的连接配置与生成预设设置为 Step 2b 派生的 `-orchestrator` 预设。
3. 在**迭代**区域确认迭代 AI 使用 `plugin-only` 预设（或留空以跟随工作台默认设置）。

## Step 4 —— 将记忆图的抽取与召回交给 Agent

切换到**工作台 → 记忆图 → 设置**：

- **启用** ✓ 保持开启
- **自动抽取** ✗ 关闭（交给 Agent 团队里负责整理记忆的子 Agent）
- **自动压缩** ✗ 关闭（Agent 收尾时一并处理）
- **启用记忆召回注入** ✗ 关闭（Agent 团队会在起草前自行执行一轮召回）

![记忆设置：抽取、压缩、召回都交给 Agent](/images/recipes/agent-onboarding/step-04-memory-toggles.png)

::: info 想完全使用「记忆图内置的抽取、召回和压缩」
默认 Director 配置将抽取 / 召回 / 压缩纳入自身职责。如果你更信任记忆图内置的链路（已经配置好多模型路由、Hybrid + Rerank 等），则：

1. 将**自动抽取**、**自动压缩**、**启用记忆召回注入**重新启用
2. 在 [Step 6 的编排 AI 迭代](#step-6) 里告诉 AI：「我不想让 Agent 管理记忆，自己用内置的记忆图就够了」
3. 在**改动清单**中逐条审阅并应用即可
:::

## Step 5 —— 选一个搜索引擎

打开**扩展 → 搜索工具**，**搜索提供方**默认是 `DuckDuckGo（无需登录）`——保持默认即可。如需更换引擎，从下拉中选择其他提供方，例如自托管的 `SearXNG（自定义实例）` 或任一需要 API Key 的提供方。

![搜索引擎选择](/images/recipes/agent-onboarding/step-05-search-provider.png)

::: info 顶部开关与本流程的关系
**暴露工具给主模型** 和 **请求前运行搜索 Agent** 是搜索插件**相互独立**的工作模式，与 Director 无关——本流程通过 Director 的搜索子 Agent 执行搜索，这些开关均**无需启用**。

如果不使用 Director 也需要搜索能力，请参阅[搜索插件](/zh-CN/features/search-tools)的「工作模式」。
:::

## Step 6 —— 在工作台 AI 迭代中定制编排 {#step-6}

打开**工作台 → AI 迭代 → 编排**（或在**编排**工作区顶栏点 **AI** 按钮），这是后续所有自定义的入口。

![AI 迭代 —— 编排](/images/recipes/agent-onboarding/step-06-iter-studio-director.png)

在顶部的**改哪一份**切换编辑作用域：

- **全局** → 编辑**全局**默认方案，所有未做覆写的角色卡均继承该方案
- **角色单独的** → 编辑**这张卡的专属方案**，仅对该卡生效，并随卡导出 / 导入

::: tip 在角色卡上调出的优秀编排可以提升为全局
如果为某张卡迭代出一套特别合用的 Director 方案，可以在**工作台 → 编排 → 准备阶段**点击**保存到全局**（或导出 JSON 后在全局作用域导入）。记忆结构同理。
:::

### 全局作用域：可使用的指令

- 「我不想让 Agent 管理记忆，请去掉负责抽取和召回的 Agent」
- 「我不想让 Agent 联网搜索同人设定，请去掉负责搜索的 Agent」
- 「读取世界书里的图像生成指导，加一个子 Agent，在正文起草完成后构思插画的插入位置和提示词」
- 「读取世界书里的变量更新指导，加一个子 Agent，在正文起草完成后构思变量如何更新」

### 角色卡作用域：可使用的指令

- 「结合这张卡的世界观和当前剧情，给主 Agent 加一段专门的写作纪律」
- 「这张卡有自定义的体力 / 心情变量，负责整理记忆的子 Agent 抽取时优先填这几个字段」
- 任何与当前角色卡题材强相关、不适合放入全局配置的指令

在**改动清单**中逐条审阅并应用即可。如果结果与预期不符，可在**改动记录**中撤销，或在**编排 → 准备阶段**重置回默认 Director 方案。

## 可选步骤 —— 让 AI 配置记忆结构

记忆图结构同样可以由 AI 修改。切换到**工作台 → AI 迭代 → 记忆图配置**；需要修复当前聊天里的节点时，选择**记忆图内容**。

![记忆结构 AI 迭代](/images/recipes/agent-onboarding/step-07-schema-studio.png)

记忆结构同样区分**全局**与**角色单独的**作用域，角色卡上的结构随卡导出。可以针对题材定制，例如：

- 修仙题材：给角色加「修为境界」「灵脉」字段
- 政治题材：新增「派系」节点类型，记录派系关系和敌对图
- 生存题材：新增「物品」节点，追踪道具的耐久、状态

## 实际运行

返回主对话发送一条消息，即可在**运行面板**悬浮窗中实时看到 Agent 团队的执行过程：

![Director 一回合内 Agent 团队的产出](/images/orchestrator/director-takeover/director-real-final-body.png)

- **起草前侦察**：各自给出 `Item / Source / Why`，列出与当前剧情相关的角色、事件、世界书条目
- **中段头脑风暴**：从多个角度并行起草剧情结构草图，供主 Agent 选择
- **起草后评审**：子 Agent 对主 Agent 的草稿提出评审意见，由主 Agent 决定采纳哪些修改
- **收尾整理**：把这一回合新出现的事实写回记忆图

在**运行面板**悬浮窗展开任意助手行（或点击**查看运行详情**跳转到**工作台 → 编排 → 运行**），即可查看模型思考与每次工具调用的入参和返回。

如果结果不满意，在运行面板点击**结果不满意？AI 诊断**，即可带入这次运行的轨迹回到[编排 AI 迭代](/zh-CN/features/orchestrator/iteration-studio)继续修改。
