# 给一张角色卡做专属编排

本页演示如何把一张有严格输出格式的角色卡改造成专属编排：从一句需求生成工作流，用模拟找出 AI 八股并据此改进提示词与 Skills，再让工作台写一个格式校验工具。

全过程由 AI 迭代工作台完成。示例使用一张社区中「输出格式严格、变量更新繁琐」的同人卡，方法适用于所有带格式硬要求或专属设定的角色卡。

---

## 用一段需求定制专属编排

导入角色卡并选中后，从「扩展 → 多 Agent 编排」打开面板，点击 **打开编排编辑器**。

![编排编辑器打开后](/images/recipes-card-customization/01-editor-opened.png)

顶部第一栏标明当前角色卡、所用的执行模式，以及当前编辑的是「全局」还是「角色卡覆盖」配置。本次工作目标是**角色卡覆盖**——所有改动只作用于这张卡，不会污染其它卡。

右上角点击 **打开 AI 迭代工作台**。

![工作台刚打开](/images/recipes-card-customization/02-studio-fresh.png)

工作台左侧为对话区，右侧实时呈现当前编排的流水线（主代理与全部子代理）。在输入框输入以下需求：

> 请给本角色卡定制一个专属编排，把全局的默认配置改成更贴合这张卡的版本。

![输入框里写好定制请求](/images/recipes-card-customization/03-prompt-typed.png)

点击 **发送**。工作台读取角色卡内容与世界书，列出当前可见的 Skills，随后开始改写主代理提示词、新增对这张卡有意义的子代理、调整可见 Skills 集合。改动会弹出一张变更审阅卡片，绿色为新增，红色为删除；审阅后点击 **应用到角色卡覆盖** 即写入。

![一次变更审阅卡](/images/recipes-card-customization/04-review-card.png)

如果需要细看，可在卡片内展开「逐行差异」；卡片顶部的一句话说明修改了哪个字段。

::: tip 提示
若不愿意逐条手动审阅，可在输入框下方勾选 **自动应用变更**。下一节「标注八股并改进」在自动应用模式下会更顺畅。
:::

数轮迭代后，工作台会用一段话总结改动内容与改动贴合这张卡的理由。

![工作台执行完成，AI 总结](/images/recipes-card-customization/05-customize-summary.png)

至此，这张角色卡获得专属编排，下次给它发送消息时即采用该配置。

---

## 执行模拟，标注八股，让工作台改进

定制完成并不代表结束，AI 写出的提示词仍可能重复自身的惯用表达。在中文角色扮演圈中，这类套话通称为「八股」。其中最常见的一种是**序数与量词构成的「计数体」**：

- 动作拆分：将一个连贯动作分成可数的细段，如「一寸一寸往回缝」「钻了半寸又停住」；
- 节奏拍数：把声音或呼吸量化为拍子，如「三下，停半拍，又三下」；
- 程度量化：用「一点」「半分」之类模糊数词代替真正的感受动词，如「忽然弱了一点」「弱了半分」。

孤立出现一次没有问题，但一段叙述反复使用同类计数结构后，文本会退化为 AI 分镜报告——读者听见的是计数，而不是"有人在经历这一刻"。

工作台提供 **模拟** 功能：在不真正向聊天写入消息的前提下，让当前编排执行完整流程并展示产出。我们用它来检测八股。

::: tip 提示
模拟继承当前聊天的全部上下文：已发生的对话记录、当前激活的世界书与 Skills、当前的预设与连接配置。模拟呈现的是「如果此刻在这张卡上发送一条消息会得到什么」，而不是脱离上下文的运行。如果想更换上下文测试，先在主界面切换聊天或调整世界书，再回到工作台。
:::

回到工作台输入框：

> 请用「我坐起身」作为用户输入，执行一次模拟，并展示给我审阅。

工作台调用模拟工具，执行一轮完整的主代理与所有子代理。Director 模式执行全套流程需要几分钟，请耐心等待。模拟结束后弹出 **模拟回顾** 窗口：

![模拟回顾弹窗：主代理输出与各子代理跟踪](/images/recipes-card-customization/06-sim-baseline.png)

模拟回顾窗口默认展开各段落，向下滚动即可看到主代理最终回复全文。我们浏览这段文本，选出「AI 腔调」较重的短语。

点击 **批注模式**——切到开启后，**在产出文本里用鼠标选中**任意一段，所选区域自动呈黄色高亮，旁侧出现批注输入框。在批注框内简述不满意之处即可（一两个词通常足够）。

![本轮模拟标注了一处量词计数八股](/images/recipes-card-customization/07-sim-baseline-annotated.png)

本轮基线中选择了一处作为示例：

| 选中的片段 | 批注 |
|---|---|
| "连闪了五下"（头顶警报灯的反复闪烁） | "五下"将视觉变化转换为次数，"光闪 → 数次数"是将感官事件抽象为数据点的典型 |

标注完成后点击窗口底部 **提交并继续**。工作台将这条批注视为「症状」反馈给 AI：AI 看到的不是孤立的不满意短语，而是带上下文位置的问题清单，可以据此反推根因。常见情况下，根因不在某个子代理写得不够细，而在于一条共性规律尚未被任何提示词承接。

![工作台根据批注做根因诊断](/images/recipes-card-customization/08-improvement-thread.png)

本次迭代中，工作台把这条批注归入「量词计数八股」一类：将真实的体感、动作、时间、身体拆解为「数字 + 量词」的可计数刻度。它没有立即修改，而是先与用户确认：该规则是绝对禁律，还是需要保留例外？在用户明确「无例外」后，工作台读取审稿子代理实际加载的 Skill，而不是名称最接近的另一个，将规则写入该子代理在运行时真正会读取的位置，并把原句作为反例写入其中，附以「独立禁律、字面命中即记录、与上下文是否温暖、诗化、物理写实或口语自然无关」的明文。这样下一轮模拟时，voice_critic 才会真正检测到此类违例。

::: warning 重要
工作台不会在主代理提示词中加入「不要说 X」这类字面禁令，这种逐处修补无法解决根本问题。它会寻找触发八股的根本原因（哪个子代理审稿写得过于粗略、哪条 Skill 缺少禁律），并从该处修复。
:::

随后**再次执行模拟**：

> 修改完成后，再执行一次模拟，观察序数、量词计数体是否减少。

新弹出的回顾窗口中，先前被标注的几条八股短语应明显减少甚至消失。

![改进后的模拟回顾](/images/recipes-card-customization/09-sim-after.png)

将两次回顾并排比较，差异可以直接观察：基线中反复出现的「光闪 → 数次数」叙述节奏（「一下，两下，停一会儿，再三下」「闪了三下」「连闪了五下」）在改进版中基本不再出现。改进后这一轮的终稿中，量词计数（一下、一节、一刻、一档、几下等）共命中 5 次，均不再出现在节奏拍点上，改用「半度」「一根管子」这类描述指代。仍有残余时，重复「标注—模拟」循环，通常两到三轮即可。

## 让工作台写一个自定义校验工具

这张角色卡对输出有硬要求：回复结尾必须附带 `<overall>` 总览与 `<UpdateVariable>` 变量更新两个标签。主代理在专注于叙事时容易遗漏这两个标签，导致角色卡的状态机器读不到本轮更新，下一轮的剧情上下文也随之失准。

针对这类需求，无需亲自编写代码或修改主代理提示词，**只需用自然语言把需求告知工作台**：

> 这张角色卡的输出格式有要求，回复结尾必须有 `<overall>` 和 `<UpdateVariable>` 两个标签，不要遗漏。

![向工作台描述格式要求](/images/recipes-card-customization/11-tool-prompt.png)

工作台会自行判断如何实现：这是一个可以由代码精确判定的格式检查问题（字面匹配），适合通过**自定义工具**解决；而被检查与提醒补全的执行者本就是创作正文的主代理，因此工具应挂载到主代理上，由主代理在结束时调用。基于这一判断，工作台会自动完成一组配套改动：

1. **查清运行时 ctx 的结构。** 工作台先核对可用的运行时接口和数据结构，必要时查阅文档，不依赖猜测。
2. **起草函数体并 dry-run。** 工作台向函数体传入样本参数，在沙箱中试运行一次，让运行时异常在你被请求批准之前暴露出来。
3. **写入校验通过的工具。** 工作台创建待审卡片；工具采用只读模式，内部一段 JavaScript 读取本轮的草稿快照并检查结尾标签。对应的启用开关会自动打开，下一轮主代理即可看到这个工具。
4. **修改主代理的系统提示词。** 工作台再修改主代理的系统提示词，追加一条规则：生成的最后一步必须调用该工具，若结果显示缺少标签则就地补全后再产出。

判断哪种机制最合适、由谁调用、需要同步修改哪些位置，这些通常需要用户提示的细节，工作台均会基于自然语言需求自行判断，无需事先以技术语言说明。

改动仍通过审阅卡展示，绿色为新增，红色为删除。**由于自定义工具会在你的浏览器中执行 JavaScript，审阅卡带有安全警示横幅**：展开工具内容核对行为，确认是只读检查、无副作用后再批准。无法理解的卡片应拒绝。

![新工具的代码审阅与安全确认](/images/recipes-card-customization/12-tool-review.png)

应用变更后，回到主代理一栏查看 **自定义工具** 列表，新工具已包含其中并默认勾选启用。

![工具已安装](/images/recipes-card-customization/13-tool-installed.png)

让工作台再次执行模拟，确认主代理确实按规则调用了工具：

> 再次执行模拟验证。

![模拟跟踪里出现该工具的调用记录](/images/recipes-card-customization/14-tool-invoked.png)

跟踪中可以看到这次工具调用：主代理在草稿写到尾部之后调用该工具一次，工具返回检查结果，主代理据此判断是否需要补全标签。

## 接下来

- 这一流程同样适用于「输出长度」「OOC 规范」「世界观禁词」等专属约束：把「什么是好」用一段话告知工作台，由它组装编排。
- 想了解自定义工具能访问哪些运行时信息，见 [自定义工具](/zh-CN/features/orchestrator/custom-tools)。
- 想为工作台再安装一条全局通用的 Skill，见 [用 Skills 调教 RP 输出](/zh-CN/recipes/rp-skills-walkthrough)。
- 若对工作台修改出的某个子代理不满意，回到编排编辑器手动编辑即可；工作台用于提高效率，并非必经步骤。
