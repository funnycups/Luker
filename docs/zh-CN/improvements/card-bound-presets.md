# 角色卡绑定预设与人设

角色卡作者可以让角色卡携带一个或多个推荐的聊天补全预设，以及一个默认人设（Persona），这样卡在导入后就能直接跑在作者设计的采样与提示词形态下。该功能构建在[预设解耦](/zh-CN/improvements/preset-decoupling)之上——连接字段始终会被剥离，导出的角色卡永远不会带 API key 或端点信息。

## 角色卡携带推荐预设

一张角色卡可以内嵌任意多个聊天补全预设，每个预设有自己的名字和内容。加载带内嵌预设的角色时，Luker 会：

1. 在聊天补全预设选择器顶部渲染一个「本卡内嵌」optgroup，列出该卡携带的所有预设。
2. 下方是「本地」组，展示你本地保存的预设。
3. 若卡上标记了默认预设，自动选中它。

「本卡内嵌」选项是运行时选项——不会新增到你的全局预设库，也不会覆盖同名的本地预设。切换到别的角色时，「本卡内嵌」组会从选择器里移除。

::: info 连接字段永远不会离开角色卡
每个存进角色卡的预设都会经过与「预设解耦」相同的字段分类器过滤：API 端点、密钥、模型、代理密码等连接字段在写入时被剥离。加载「本卡内嵌」预设时只会应用采样和提示词结构相关的字段，无法悄悄把你的请求路由到卡作者的端点。
:::

## 把当前预设绑定到角色

在角色头像旁的角色管理下拉里选「绑定当前对话补全预设」。Luker 会把当前选中的预设加入这张卡的内嵌集合，并设为该卡的默认。

- 卡上还没有同名预设时，作为新槽加入。
- 卡上已经有同名预设时，Luker 会问你是否用当前设置覆盖卡上那一份。

若当前选中的预设本身就是「本卡内嵌」选项，绑定会被拦下——这种情况没有可提升的预设，Luker 会给出一条提示，而不是静默无操作。

## 管理已绑定的预设

「管理已绑定的对话补全预设」为当前角色打开一个对话框，列出所有卡内嵌槽位。每一行提供：

- 「设为默认」——切换加载卡时 Luker 自动应用的槽位。
- 「覆盖为当前」——用当前选中预设的内容替换该槽位的内容，槽位名保持不变。
- 「从本地更新」——用同名的本地预设覆盖该槽位内容。当本地没有同名预设时按钮不可点。
- 「删除」——删除该槽位。若删的是默认槽位，默认会被清空，直到你重新设置。

对话框底部的「从本地预设添加」控件让你挑一个本地预设加为新槽——同名槽已存在的会自动从下拉里过滤掉。

## 一次性清空所有绑定预设

「清除已绑定的对话补全预设」会一次性清掉当前角色卡上的全部内嵌槽位，只需一次确认。当你想把角色卡还原成「无推荐」的干净状态时用它。

## 直接编辑卡内嵌预设

当选中的预设是「本卡内嵌」槽位时，你在 Prompt Manager、采样滑块、提示词分组、扩展开关等常规界面里做的编辑，都作用在该角色的卡内嵌副本上，而不是你的本地预设库。要提交这些编辑，点「更新当前预设」按钮。同名的本地预设保持不变。

如果你想让编辑变成一份独立的本地预设，请用「另存预设为」，它会把内容以新名字注册进全局列表。

::: tip Prompt Manager 对卡内嵌预设的迭代是透明的
Prompt Manager、补全预设助手 (CPA)，以及任何最终走到「更新当前预设」的 AI 迭代流程，都通过同一个 dispatch。对卡内嵌预设的迭代会写回该卡槽位，没有额外的「提交到卡」步骤。
:::

## 编排器 agent 预设优先从卡上读

多 Agent 编排 profile 里，每个 agent 引用的聊天补全预设都是**按名字**指向的。当加载了带内嵌预设的角色卡时，agent 名字解析规则：先查卡上的内嵌槽位，再查本地预设，最后回退到全局默认。这意味着一份随卡导出的编排 profile 是端到端可跑的：接收方无需再单独导入匹配的预设。

编排器抽屉里的「保存到角色卡覆写」在持久化前会检查引用的预设名字。若有 agent 引用的预设还没内嵌到卡上，Luker 会弹窗询问：

- **全部内嵌**——把每个引用预设的本地内容嵌入卡里，让编排 profile 在导出后依然自给自足。
- **只存名字**——保存编排 profile 但不嵌入预设内容。接收方若没有同名本地预设，该 agent 会走运行时默认回退。
- **取消**——中止保存。

## 角色卡携带默认人设

一张角色卡可以绑定一个或多个推荐人设。打开卡时：

- 若你还没选人设，Luker 会切到卡推荐的人设。
- 若你已选了人设，Luker 会提示当前人设与卡推荐的不一致，由你决定对齐还是保留自己的。

绑定的人设会随角色卡一起导出，接收方导入后能看到同样的推荐。

## 导入导出往返

绑定预设、默认人设、编排器覆写都是角色卡数据的一部分。标准角色卡导出（PNG 或 JSON）会一起带走；标准导入会一起恢复。不需要额外的伴生文件来分发。

## 依赖

角色卡绑定预设功能依赖[预设解耦](/zh-CN/improvements/preset-decoupling)。没有解耦提供的字段分类器，就无法在把预设嵌入角色卡时安全剥离连接字段。
