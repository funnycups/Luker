# WebSocket 代理

WebSocket 代理用一条持久连接传输 AI 生成请求，替代每次生成都新建 HTTP 连接。它面向移动网络、跨国链路和会中断长连接的网络环境，用来减少生成中途失败。

## 解决什么问题

传统模式下，每次生成都是一次独立的 HTTP 请求。网络短暂波动、移动网络切换或代理超时都可能中断请求，已经生成的内容随之丢失。

WebSocket 代理在页面与 Luker 服务端之间建立一条长连接，所有生成请求复用这条连接。连接断开后会自动重连；生成过程中断线，重连后从断点继续接收内容，而不是从头开始。

```d2
direction: down

HTTP: "传统 HTTP：每次生成新建连接" {
  H1: "客户端"
  H2: "服务端"
  H3: "客户端"
  H4: "服务端"
  H5: "客户端"
  H6: "服务端"

  H1 -> H2: "建立 TCP + TLS"
  H2 -> H1: "响应后断开" {style.stroke-dash: 3}
  H3 -> H4: "建立 TCP + TLS"
  H4 -> H3: "响应后断开" {style.stroke-dash: 3}
  H5 -> H6: "建立 TCP + TLS"
  H6 -> H5: "响应后断开" {style.stroke-dash: 3}
}

WS: "WebSocket 代理：持久隧道" {
  W1: "客户端"
  W2: "服务端"

  W1 <-> W2: "建立一次连接"
  W2 <-> W1: "心跳保活 · 多个请求复用同一条连接" {style.stroke-dash: 3}
}
```

## 适合的场景

- 手机在 Wi-Fi 与蜂窝网络之间切换。
- Luker 部署在远程服务器，通过不稳定的网络访问。
- 生成长回复，普通 HTTP 连接容易在中途被代理或防火墙断开。
- 企业网络会主动切断长时间空闲的 HTTP 连接。

代理对用户透明。Luker 会在需要时使用它，不需要额外配置。

## 可靠性机制

**心跳保活**：客户端与服务端定期交换心跳，避免中间设备因连接空闲而断开。

**自动重连**：连接意外断开后，客户端会重新建立连接，不需要手动刷新页面。

**断点续传**：生成过程中如果连接短暂中断，重连后从上次收到的位置继续，内容连续且完整。

**任务清理**：长期没有活动的生成任务会被清理，仍在持续输出的任务不受影响。

## 安全

代理不会绕过登录、会话或 CSRF 检查。建立隧道时验证当前登录状态，后续每个请求仍然经过与普通 HTTP 相同的中间件。连接凭证短时有效且只能使用一次，不经过 URL 传递。
