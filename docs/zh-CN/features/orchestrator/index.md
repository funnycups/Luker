# 多 Agent 编排

精心铺垫的场景仍可能被一条回复破坏：跳过刚建立的节奏、忘记此前确立的世界规则、出戏总结，或者仓促收尾本应留到后面的伏笔。一次生成要同时满足人物一致性、上下文、世界规则、情节推进与文笔，很难每项都到位。

编排器在主模型动笔之前，先运行一组 Agent 完成准备工作：提取近期聊天中的关键状态、确定当前生效的世界规则、规划这一回合的推进方向并审校。产物取决于执行模式：多数模式输出一份精简的编排结果注入主模型的提示词，Director 模式由编排器内的主笔直接写出回复正文。

**编排器自带可用的默认 Spec 工作流，启用即可运行。** 所有执行模式均可在**工作台 → 编排**中查看和编辑，也可通过**工作台 → AI 迭代 → 编排**用自然语言调整。

::: info 它什么时候触发？
编排器在普通回复、继续、重新生成、滑动切换和扮演时运行，在世界书解析之后、主模型回复之前。运行轨迹实时展示在运行面板悬浮窗与工作台的运行视图中。
:::

## 快速开始（使用默认编排）

默认 Spec 已配置完成，启用后即可运行。

### Step 0 —— 你需要先有什么 {#step-0}

- 主对话已能通过聊天补全接口正常生成回复
- 当前对话至少有数轮聊天记录

### Step 1 —— 启用编排器 {#step-1}

打开**工作台**（魔杖菜单 → **工作台**、右下角入口、快捷键 `Alt+W`，或**扩展 → 多智能体编排 → 在工作台中打开**），切换到左侧的**编排**标签页，打开**启用编排**开关。

![编排器启用开关](/images/orchestrator/orch-toggle.png)

### Step 2 —— 给各 Agent 选模型 {#step-2}

在**编排 → 设置**的默认 API 与预设区域，指定各 Agent 使用的连接配置与生成预设；也可以在**流程**视图里点选单个助手，单独指定它的模型与预设。

::: tip 成本
编排器的每个节点都会产生模型调用。主对话使用高价模型时，可以为编排器选择更小的模型；需要更高质量时，也可以为每位助手单独指定连接与预设。
:::

### Step 3 —— 直接发一条消息 {#step-3}

在主对话中发送一条消息，其他设置保持默认。主模型回复之前，默认 Spec 工作流会在后台执行。

### Step 4 —— 查看执行过程 {#step-4}

运行开始时，悬浮**运行面板**会在桌面端自动打开（窄屏上从底部升起）。面板实时更新轮次与进度；展开任意助手行，即可查看思考过程、工具调用和返回结果。

![编排器开始运行时的面板](/images/run-panel/01-panel-initial.png)

模型流式输出时，面板在原地实时更新：

![流式过程：思考、文本与工具分节实时填充](/images/run-panel/02-panel-streaming.png)

展开任意工具调用，能看到它的入参和返回：

![工具调用展开——参数与结果](/images/run-panel/03-panel-tool-expanded.png)

窄屏下面板变成底部抽屉，可以上拉展开或下滑关闭：

![窄屏下的运行面板（抽屉布局）](/images/run-panel/05-panel-drawer.png)

在运行面板中可以执行以下操作：

- 运行中点击**停止**
- 点击**查看运行详情**，跳转到**工作台 → 编排 → 运行**查看完整泳道时间线
- **导出运行轨迹**为 JSON 文件，便于分享或反馈问题
- 运行结束后点击**结果不满意？AI 诊断**，直接带入本次运行详情跳转到**工作台 → AI 迭代 → 编排**

运行面板菜单中的**运行时自动打开**默认开启；也可以随时从魔杖菜单 → **运行面板**重新打开。

至此编排器已启用，接下来选择执行模式：

- 需要固定、可重复的流程 → [Spec 模式](/zh-CN/features/orchestrator/spec)
- 只需要一次调用注入一段引导 → [单 Agent 模式](/zh-CN/features/orchestrator/single)
- 运行哪些 Agent 需要根据中间结果决定 → [Agenda 模式](/zh-CN/features/orchestrator/agenda)
- 希望单个 Agent 反复调用工具，自行判断何时结束 → [Loop 模式](/zh-CN/features/orchestrator/loop)
- 希望由编排器内的团队直接写出正文 → [Director 模式](/zh-CN/features/orchestrator/director)

::: tip 定制入口
各模式的定制均可在**[工作台 AI 迭代](/zh-CN/features/orchestrator/iteration-studio)**中完成：用一句话描述目标，在**改动清单**里逐条审阅后应用，并支持随时撤销。
:::

## 选你的执行模式

| 模式 | 工作台显示名 | 是什么 | 何时用 | 技能范围 | 详细文档 |
|---|---|---|---|---|---|
| **Spec**（默认） | **流程** | 固定的阶段与节点流程 | 默认模式。需要可预期的流程 | 每个节点可单独选择可见技能 | [Spec 模式](/zh-CN/features/orchestrator/spec) |
| **单 Agent** | **单助手** | 只有一个独立节点的精简流程 | 成本低、速度快。不需要多 Agent 协作 | 在该节点上选择技能 | [单 Agent 模式](/zh-CN/features/orchestrator/single) |
| **Agenda** | **调度** | 调度员根据情况动态派遣其他助手 | 流程无法预先固定 | 调度员与每个被派遣的助手分别选择 | [Agenda 模式](/zh-CN/features/orchestrator/agenda) |
| **Loop** | **循环** | 单 Agent 在会话中反复调用工具，自行判断何时结束 | 探索性研究、动态决策 | 在研究员上选择 | [Loop 模式](/zh-CN/features/orchestrator/loop) |
| **Director** | **导演** | 主笔带子助手团队探索上下文并创作正文 | 高质量长篇角色扮演 | 主笔与子助手分别选择；出厂自带默认技能 | [Director 模式](/zh-CN/features/orchestrator/director) |

在**编排**工作区顶栏的模式选择器中切换模式。在**准备阶段**中，Spec 与 Agenda 支持互相复制助手列表。

::: info 技能范围
所有模式都可以限制每个 Agent 能看到哪些技能。Director 在出厂配置中已绑定默认技能，其他模式的 Agent 默认可以看到全部已安装技能。技能的作用方式见 [编排器集成](/zh-CN/features/skills/orchestrator-integration)。
:::

## 通用配置

这些设置位于**工作台 → 编排 → 设置**，在所有模式间共享。

### 结果注入

编排器的最终输出会注入主模型的提示词（Director 模式由主笔直接写出正文，使用结果即正文）。

| 设置 | 默认 | 说明 |
|---|---|---|
| 注入位置 | `在聊天深度` | 编排结果在提示词中的位置 |
| 注入深度 | `0` | 在该位置的深度 |
| 注入角色 | `System` | `System` / `User` / `Assistant` 之一 |
| 自定义指令 | 默认值为一句话 | 添加在编排结果之前 |

编排结果绑定到触发编排的用户消息楼层。同一楼层切换分支时复用现有结果；配置变更后重新应用最新结果。

### 角色卡绑定

在**编排 → 准备阶段**（或在 **AI 迭代 → 编排**选择角色卡作用域）可以把编排方案保存到当前角色卡：

- 方案随角色卡导出，导入者自动获得推荐工作流
- 切换到这张卡时自动应用其工作流
- 通过**这张卡固定的模式**可以为角色卡锁定执行模式（Spec / Agenda / Loop / Director 均支持）
- 点击**清除这张卡上的预设**即可恢复使用全局方案

### 导入导出

在**编排 → 准备阶段**顶部的方案栏中，所有模式（Spec / Agenda / Loop / Director）均支持导出或导入 JSON，也可以通过保存到全局或保存到角色卡实现跨作用域复用。

### 通用配置参考

**编排 → 设置**集中管理默认 API 连接与生成预设、当前模式的运行上限、跨模式上限（参考的最近回合数、工具调用重试次数、每分钟请求上限）、结果注入设置以及迭代 AI 配置。
