# 编排预设

编排模式（Spec、Agenda、Loop、Director）在全局与角色卡作用域各维护一份预设库。预设保存该模式编排面板里的全部内容：系统提示词、工具开关、子代理、规划配置、运行上限和编排结果注入策略。提示词预设和 API 连接只按名称引用，运行时才解析。

本页说明预设栏的操作、两种作用域的区别，以及预设之间如何引用。

- **全局** —— 预设存放在扩展设置里，对所有聊天可用。
- **角色卡** —— 预设存放在角色卡本身，导出角色卡时一并导出。

::: tip 分库保存
各模式的预设结构不同，因此分库保存。切换执行模式时显示当前模式的库。
:::

## 预设栏

预设栏位于每种模式编辑面板的顶部：

![预设栏 —— director 模式](/images/orchestrator-presets/01-director-default.png)

预设栏提供以下操作：

- **下拉菜单** —— 列出当前模式与作用域下的全部预设。选中一项后，编辑器加载该预设的内容。
- **新建** —— 使用当前模式的出厂默认数据创建一份新预设。
- **复制** —— 克隆当前激活预设并指定新名称，副本成为新的激活预设。
- **重命名** —— 修改名称。引用该预设的配置继续有效。
- **删除** —— 删除该预设。如果删除的是当前激活预设，列表中的下一份会自动成为激活预设。如果整个库被删空，下一次读取时会用出厂数据重新填充 `Default`。
- **导入 / 导出** —— 使用标准的可移植 JSON 格式。导入时指定名称，加入当前库；导出将当前激活预设写入磁盘。

在面板中进行的编辑会写回**当前激活**预设，无需显式保存；关闭面板或切换预设时，当前状态已经持久化。

## 全局作用域 vs 角色卡作用域

没有加载角色卡时，预设栏展示该模式的全局库。在这里改动会影响所有未使用角色卡预设的聊天。

加载了角色卡后，下拉分成 **角色卡** 和 **全局** 两组，其中一组处于选中状态。该选中项决定使用哪个库：

- **选中角色卡预设** —— 卡上的预设对这个角色生效；这次聊天中全局激活预设被忽略。
- **选中全局预设** —— 这次聊天以全局激活预设为准。卡自己的库原样保留在卡上，随时可以从同一个下拉切回卡上的任何预设。

切换组会立即写入卡的激活槽位并随卡持久化，该选择随角色卡导出与导入。

如果这张卡还没有自己的预设库，角色卡组为空。在选中卡预设的状态下保存一次编辑，卡的预设库随之创建。

::: info 角色卡导出时带上自己的预设库
导出角色卡时会把卡自己的预设库一并打包，因此在另一台机器导入这张卡时，卡上的预设也会一并导入。
:::

## 编排预设和提示词预设、API 预设的关系

编排预设是一次生成里相互独立的层之一，另外两个是 SillyTavern 的提示词预设和连接配置：

| 概念 | 控制什么 | 存在哪里 |
|---|---|---|
| 编排预设 | 子代理、工具、规划 Agent、Loop 上限、系统提示词、编排结果注入 | 扩展设置或角色卡上 |
| 提示词预设 | token 预算、采样器、提示词顺序、越狱 | SillyTavern 预设 |
| API 预设 | 端点、模型、API 密钥 | API 连接配置 |

编排预设按**名字**引用提示词预设和 API 预设。例如一份 Director 预设可以把评审子代理指定为强模型预设，其余子代理使用快速预设。切换编排预设只更换编排层；提示词预设和连接配置保持不变。

名为 `审讯节奏` 和 `重叙事密度` 的两份预设，可以共用同一份提示词预设和连接配置，只在编排形态上有差别：不同的子代理、不同的规划 Agent 指令、不同的注入深度。在预设栏中切换即可生效。

## Agent 提示词预设解析优先读角色卡

当一份编排预设按名字把某个 agent 指定为某份提示词预设（`Sonnet · 慢节奏评审`、`Haiku · 快速` 等）时，这个名字在生成时才解析。查找顺序：

1. 当前角色的卡内嵌预设集合：卡上存在同名内嵌预设时直接采用。
2. 你本地的聊天补全预设库。
3. 前两者均未命中时，回退到编排器设置中指定的全局运行时默认。

角色卡自带推荐预设时，卡优先的顺序决定最终采用哪一份：编排配置与它引用的预设一起分发，接收方无需单独导入。同名时，卡上的副本在该角色范围内优先。

加载角色卡后，编排器抽屉里每个 agent 的预设选择器顶部会显示「本卡内嵌」分组，列出卡上的内嵌预设，可与本地预设一并选择。

## 把编排配置提交到角色卡时按需内嵌引用的预设

向当前角色卡提交编排配置时，Luker 会先预检 agent 引用的提示词预设名字，查出哪些还没内嵌到卡上。这里的「提交」既包括编排器抽屉里的「保存到角色卡预设」，也包括「AI 迭代工作台」弹窗里的「应用到角色卡」——这些入口共用同一次预检。

若有未内嵌的引用，会弹出汇总窗口列出它们，提供以下动作：

- **全部内嵌** —— 把每个引用预设的本地内容复制到角色卡，使编排配置在导出后可以完整运行。
- **只存名字** —— 按原样保存编排配置，不嵌入预设内容。接收方若没有同名本地预设，相关 agent 会使用运行时默认回退。
- **取消**——中止提交。

弹窗只在提交时出现。

角色卡槽位如何管理、编辑、剥离连接字段，详见[角色卡绑定预设与人设](/zh-CN/improvements/card-bound-presets)。

## 默认预设

默认预设是普通预设，可以重命名、编辑、删除。

删光一个库里的预设后，下次读取时会从出厂数据重新生成默认预设。想恢复出厂配置，删除全部预设即可。

## 用法举例

预设栏支撑的几种常见用法：

- **同一张卡用多份预设** —— 日常场景使用一份响应快、成本低的预设，重要场景使用一份速度较慢、密度更高的预设。均保存在角色卡作用域下，需要时从下拉中选择。
- **把角色卡预设提升为全局** —— 把卡上的激活预设导出，再把预设栏切到全局作用域，导入这份 JSON。全局库中也会包含同一份预设，对所有聊天可用。
- **试一份预设但不承诺** —— 复制一份当前激活预设，在副本上修改。如果实验未成功，从下拉中切回原版即可恢复。
- **把调好的编排和角色卡一起交付** —— 在角色卡作用域中调整预设，确认下拉中选中的是卡上的预设，然后导出角色卡。导入后即可获得同一套编排。
