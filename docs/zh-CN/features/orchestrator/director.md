# Director 模式

Director 是编排器的接管模式：这一回合的正文由编排器内的写作团队直接完成，主模型不参与。它面向高质量长篇角色扮演：先侦察上下文并起草，再由文风与连贯性评审提出修改意见，主代理修订后提交。

## 与其它模式的区别

| | Spec、Agenda、Loop | Director |
| --- | --- | --- |
| 谁写正文 | 主模型读取编排结果后创作 | 编排器内的主代理直接创作 |
| 编排器产出 | 一份精简的编排结果 | 完整可发送的消息正文 |
| 主模型本回合 | 正常生成回复 | 不参与 |
| 适合 | 让主模型在既有上下文上持续产出 | 让多视角写作团队直接交付成稿 |

主聊天窗口只显示最终叙事，草稿、评审与修订过程记录在运行面板中，可展开查看。

## 适合的场景

- 长篇角色扮演，角色一致性、文风一致性和连续性同时重要。
- 希望「起草 → 评审 → 修订」由流程保证。
- 不同环节使用不同模型：规划使用成本较低的模型，评审使用更强的模型。

不适合追求低延迟的日常对话。Director 一回合要执行多轮工具调用和多次子代理派遣，开销明显高于其他模式。

## 工作方式

```d2
direction: down

start: "新回合开始\n主模型不参与本回合" {
  shape: oval
  style.fill: "#e8f5e9"
}

loop: "主代理主导写作" {
  style.fill: "#e1f5ff"

  think: "读取当前草稿\n决定下一步" {
    style.fill: "#fffde7"
  }

  decide: "需要什么？" {
    shape: diamond
  }

  consult: "咨询子代理" {
    style.fill: "#fff3e0"
    pre: "起草前侦察\n用户意图 · 近期聊天 · 记忆图 ·\n世界书 · 待兑现的笔记 · 角色认知边界" {
      style.fill: "#fffde7"
    }
    mid: "结构构思\n从不同角度给出情节草图" {
      style.fill: "#fffde7"
    }
    post: "起草后评审\n文风 · 连贯性" {
      style.fill: "#fffde7"
    }
    house: "起草后整理\n写入记忆图 · 关闭已兑现的笔记" {
      style.fill: "#fffde7"
    }
  }

  research: "自行查询\n近期聊天 · 记忆图 · 世界书 · 联网资料 · 笔记" {
    style.fill: "#fffde7"
  }

  write: "起草或修订正文\n续写 · 修补问题段落 · 重读草稿" {
    style.fill: "#fffde7"
  }

  finish: "提交正文" {
    style.fill: "#c8e6c9"
  }

  think -> decide
  decide -> consult: "咨询"
  decide -> research: "查询"
  decide -> write: "写作"
  decide -> finish: "提交"
  consult -> think: "返回结果"
  research -> think: "继续"
  write -> think: "继续"
}

out: "正文进入聊天" {
  shape: oval
  style.fill: "#f3e5f5"
}

start -> loop.think
loop.finish -> out
```

1. **侦察**：主代理按需查询近期聊天、记忆图、未激活的世界书条目、待兑现的笔记和联网资料，确认当前状态、角色知道什么、哪些伏笔该在本回合推进。
2. **起草**：把初稿写入消息。
3. **评审**：文风评审检查对白是否符合人物身份与语感，是否出现数据化描写或设定误读；连贯性评审检查与聊天、记忆、世界书中的既有事实是否冲突，以及角色是否获得了剧情中未曾告知的信息。
4. **修订**：主代理接受有效的批评，忽略不成立的，必要时再评审一轮。
5. **提交**：正文进入聊天，过程记录在运行面板中。

## 默认团队

出厂配置自带一组按角色扮演调优的子代理：

- **起草前侦察**：用户意图、近期聊天、记忆图、未激活的世界书、待兑现的笔记、角色认知边界、公共 IP 设定考据。
- **结构构思**：从不同角度给出情节草图，可以并行派遣多份。
- **起草后评审**：口吻与连贯性。
- **起草后整理**：把会延续的事实写入记忆图，关闭已兑现的笔记。

这些子代理只在需要时启动。主代理根据当前草稿决定下一步派谁，不按固定顺序全部执行。

## 开始使用

1. 在扩展抽屉把执行模式设为 **Director（多代理）**。
2. 为主代理和子代理选择 API 连接与聊天补全预设。预设下拉框旁的问号按钮可以一键导入 `agent-director`。主代理与子代理可以分别配置，让侦察使用成本较低的模型、评审使用更强的模型。
3. 初次使用保留默认系统提示词。默认提示词已按侦察、起草、评审、修订的流程编写；需要修改时优先使用 [AI 迭代工作台](/zh-CN/features/orchestrator/iteration-studio)。
4. 正常聊天，在运行面板查看每个子代理的输出和最终正文。

## 配置

### 主代理

- **API 预设**：主代理使用的连接。
- **提示词预设**：主代理使用的聊天补全预设，决定上下文结构与采样参数。
- **系统提示词**：主代理的角色、工作流和结束条件。留空会发送空指令，没有隐藏默认值；「重置为默认值」可以恢复内置文本。

### 子代理

每个子代理有名称、描述、系统提示词和独立的 API 与提示词预设。描述决定主代理何时派遣它，系统提示词决定它从什么视角评审或侦察。

### 上限

- 主代理的最大工具调用轮数。
- 同时运行的子代理数量。
- 本回合累计的子代理启动次数。

### 中断行为

可以选择中断时保留半成品正文，或丢弃半成品并回到生成前状态。

## 预设建议

主代理使用的聊天补全预设服务于工具调用循环，不直接产出最终回复。关闭重复注入的内容可以让它把注意力放在任务上。

关闭：角色卡字段、用户人设、示例对话、预设里的世界书占位符。这些内容已经由编排器写入主代理看到的上下文。

保留：聊天历史、文风指令、越狱与解除拘束指令、反八股指令。聊天历史是主代理的实际输入；文风与反八股指令同时影响起草和评审。

## 单 Agent 迭代写作

如果已经明确想要的风格，不需要评审视角，可以把 Director 简化为单个主代理反复起草、回读、修改、提交。用 AI 迭代工作台描述这个目标即可：移除子代理，保留聊天、记忆图和世界书工具，让主代理自行判断何时结束。

这种配置没有评审环节，主代理的判断即为终稿。确认它在你的提示词下能稳定结束，再保存为新的预设。

## 限制

- 在普通回复、重新生成、滑动切换和继续时运行；安静生成与扮演不触发。
- 需要主流云端连接；本地 Kobold 与 Text generation WebUI 暂不支持。
- Director 运行时不注入编排结果，正文本身就是产出。
- 子代理不能再派遣子代理。它们共享主代理启用的查询工具，某一轮没有调用任何工具时结束并返回文本。
- 主代理和子代理都遵循编排器的流式传输开关。
- 消息会随主代理的每次写入或补丁实时更新；子代理的输出实时进入思考折叠。
