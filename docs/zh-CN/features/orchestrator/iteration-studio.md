# AI 迭代工作台

AI 迭代工作台是编排器的**主要定制方式**。大多数情况下无需手动编辑阶段、节点或规划 Agent 提示词：用一句话描述目标，AI 返回一份方案，逐条审批。Spec / Agenda / Loop / Director 各执行模式共用同一个工作台，只是产出物不同。

::: tip 定制入口
工作台依据当前配置生成方案，适合大多数定制需求；手动编辑用于工作台未覆盖的场景。
:::

## 打开工作台

切到想要的执行模式（Spec / Agenda / Loop），在编排器面板的操作区点击 **打开 AI 迭代工作台**。

![快速生成与迭代工作台按钮](/images/orchestrator/orch-quickbuild-button.png)

会弹出一个面板。左边是你和工作台 AI 的对话，右边是当前编排的状态。

![迭代工作台主视图](/images/orchestrator/orch-iteration-studio.png)

## 描述你想要什么

在输入框中写一句话，描述希望编排做什么。描述越具体越好。

> 例：*「我希望 AI 在每次回复前先回顾近期重要事件、保持人设一致性，并且不要轻易破规出戏。」*

![输入框带示例](/images/orchestrator/orch-iter-input.png)

点击 **发送给 AI**。

## 查看 AI 的执行过程

AI 返回一段简短计划与一份方案，展示它打算改什么。具体形态取决于当前模式：

- **Spec / Agenda 模式** —— AI 产出一份差异清单：绿色加号（新增）、红色减号（删除）、黄色（修改）。可以逐条批准或拒绝，也可以直接等待，工作台会自动迭代直到方案稳定。
- **Loop 模式** —— AI 直接修改配置：系统提示词、工具开关、轮次上限、预设路由。改动完成后告诉你结果。
- **Director 模式** —— AI 直接修改主代理与子代理的名册：提示词、工具、预设路由、技能。名册视图会标出被改动的行。

![待审批的改动](/images/orchestrator/orch-iter-diff-inline.png)

若某条改动不易理解，点击旁边的放大镜图标即可左右对比查看。

![并排差异详情](/images/orchestrator/orch-iter-diff-side.png)

## 应用

在 AI 表示没有更多建议之后，点击 **应用到全局**（到处均用）或 **应用到角色卡**（只对这张卡）。

## 工作台能干什么

- **多轮对话。** 你提交一句反馈，AI 提出一个聚焦的改动方案，由你审阅。
- **逐条审批。** Spec 与 Agenda 的改动单独批准或拒绝，可以只接受方案的一部分。
- **模拟测试。** 用当前聊天上下文执行一次工作流，世界书照常激活，结果只显示在工作台中，不写入聊天。例如询问「新加的约束节点能否拦住出戏」，工作台会展示每个节点的输出。
- **会话保存。** 每个作用域保留独立会话，不同角色卡、不同实验互不干扰。
- **回滚。** 即使已经应用，也可以撤销。
- **可折叠思考。** 推理模型的思考内容默认折叠，较长的消息同样折叠。

## 迭代示例

> **你：** *「AI 不要轻易出戏。」*
> **AI：**「在约束阶段加一个检查节点，拦截角色偏离和元评论，并启用数据化叙述检查。」 改动：新增节点、修改设置。你批准。
>
> **你：** *「让它读世界书，这样它知道世界规则。」*
> **AI：**「在约束阶段加一个世界书读取节点，让检查节点看到当前激活的世界规则。」 改动：新增节点。批准。
>
> **你：** *「模拟一个明显出戏的输入，看检查节点真能拦住吗？」*
> **AI：** 切到模拟模式，用一段越界的用户消息执行一次工作流，把检查节点的判定结果展示给你。

![模拟输出](/images/orchestrator/orch-iter-simulation.png)

> 方案稳定后选择**应用**。

## 各模式的产出差异

| 模式 | 工作台产出 | 你看到什么 |
|---|---|---|
| **Spec** | 阶段与节点的改动：加节点、删节点、改提示词模板、调执行标志、调 API 与预设覆写 | 绿/红/黄差异列表，逐条审批 |
| **Agenda** | 规划 Agent 提示词与工作 Agent 池的改动：加 Agent、改调度逻辑 | 绿/红/黄差异列表，逐条审批 |
| **Loop** | 直接修改 Loop 配置：系统提示词、工具开关、轮次上限、预设路由 | 看不到逐条差异，AI 改完后告诉你结果 |
| **Director** | 直接修改主代理与子代理名册：提示词、工具、预设路由、技能 | 名册视图标出改动行，没有逐条差异面 |

## 描述 Agent 的行为

在 Loop 等以提示词驱动的模式中，可以直接用自然语言描述期望的 Agent 行为：

> 我希望这个 agent 先读最近 5 楼，再去世界书查相关设定，最后去记忆图找有没有冲突，然后写编排结果。不要它写笔记。

工作台读取当前配置，直接修改 Loop 的系统提示词与工具开关，改完后报告结果。

## 角色卡世界书冲突处理

在以角色卡为作用域打开工作台时，AI 还会同时对照这张卡绑定的世界书。格式相关的世界书条目分为两类，处理方式不同：

- **过程强制类**——条目规定*模型运行过程中如何思考*（强制思考模板、每轮必须添加思维链前缀、「回答前先做 5W1H 检查」、「按 1 至 N 步依次执行后再回答」等）。这类条目会干扰编排：它们会在工具调用过程中触发，占用 agent 用于规划和工具调用的时间。工作台会去除格式约束，提取作者真正想要的意图（关心的话题、角度、人设习惯、场景锚点），并将其改写为叙事、人设或场景素材，作为叙事输入交给 agent 读取。
- **最终输出形态类**——条目在描述*最终给用户看到的那一条回复长什么样*（"输出必须用 markdown"、"用标签包裹回复"、"末尾附上一段总结"、"说话用诗的格式"等）。这类是合理的风格偏好，工作台会保留——只是改写措辞，使最终提交的语义明确，避免编排过程中的规划节点、工具调用节点、复审节点也被这条形式约束限制。

工作台首选只改写冲突那一句、保留条目的其它信息载荷；只有当整条几乎就是纯格式约束、没有可保留的内容时才直接禁用整条。任何情况均不会删除条目。

**审批流程。** 世界书调整以提案形式出现在产生它的助手消息下方，带**批准**与**拒绝**按钮。获准的提案在点击**应用**时写入本地世界书，被拒绝的提案丢弃，未决定的保留在面板中。输入框上方的汇总行显示待审批、已批准与已拒绝的数量；存在已批准的提案且没有待处理的编排改动时，该行会提供单独提交世界书改动的按钮。

全局编排会话不涉及世界书，该流程仅在角色卡范围内生效。

## 用工作台编写 skill

不想手动编写 SKILL.md？打开工作台并描述需求。它会起草、安装 SKILL.md，并（如有要求）挂载到对应位置——与其他改动相同的逐条审批流程。

一句话就够，自然语言：

> 帮我写一条 skill，让导演避开翻译腔。别让角色对话出现「当 X 的时候」这种句式，不要用「——」破折号分隔短句，「是吗？」改成「是吧？」这种更本地化的语气词。让导演模式下所有 agent 都看到。

审批之后，Skill 立即写入并可用。请求中说明挂载范围时（例如「让所有 Agent 看到」「给文风评审看」），工作台会一并挂好；也可以之后在 [Skill 列表](/zh-CN/features/orchestrator/skills) 中自行添加。

![工作台执行完成并安装](/images/skills/iter-studio-05-after-llm-round.png)

详见 [《用 skills 调教 RP 输出》](/zh-CN/recipes/rp-skills-walkthrough)。

## 会话管理

不同卡、不同实验各自拥有独立的会话。

![Session 列表](/images/orchestrator/orch-iter-sessions.png)

会话持久保存，刷新后保留，作用域可以是全局或某张角色卡。不同作用域的会话彼此独立。

## 边栏 —— 快速生成（Spec / Agenda）

快速生成是迭代工作台的一键模式，适用于 Spec 与 Agenda。在编排编辑器顶部 **AI 生成目标** 文本框里输入需求，点 **AI 快速生成**:

![快速生成输入区](/images/orchestrator/orch-quickbuild-input.png)

一次 LLM 调用之后即可获得完整工作流：

![快速生成结果](/images/orchestrator/orch-quickbuild-result.png)

适合以下两种场景：

1. 已经用迭代工作台调整过多次类似配置，这次只需要一个可用的模板，不想再执行完整流程
2. 只需要默认配置可用，不关心 AI 的决策过程

迭代工作台逐条呈现改动，配置可以逐步理解并继续调整。

::: info Loop 模式
Loop 配置在迭代工作台中逐步调整，快速生成仅支持 Spec 与 Agenda。
:::
