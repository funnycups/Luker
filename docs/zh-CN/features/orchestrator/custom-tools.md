# 自定义工具

自定义工具给编排器里的 Agent 增加内置能力之外的操作：查询外部服务、调用其他扩展的功能，或读取你自己的数据源。Loop、Spec、Agenda 和 Director 使用同一套工具定义，切换模式不会丢失。

## 工具来源

**其他扩展注册的工具。** 记忆图、搜索插件等在启动时注册自己的工具，这些工具自动出现在编排编辑器的自定义工具列表中，新建编排时默认启用。

**SillyTavern 插件注册的工具。** 插件通过 SillyTavern 的函数调用系统提供工具时，可以在编排编辑器中桥接，并指定它在本编排中是只读还是可写。桥接后的工具出现在单独的分组中。

**为当前编排手写的工具。** 前两种来源不足时，可以在编排编辑器中新增工具。工具随编排保存：全局编排中的工具全局生效，角色卡覆写中的工具随角色卡导出。

## 添加工具

新增工具需要填写以下字段：

- **名称**：供 Agent 调用，只能使用字母、数字和下划线，且不能与已有工具重名。
- **显示名**：在编排编辑器中展示，便于识别。
- **描述**：说明工具的用途与使用时机。
- **模式**：只读工具没有副作用；写入工具会修改状态，在模拟评审中默认跳过。
- **参数**：Agent 调用时提供的字段，按表单填写，无需手写结构描述。
- **执行内容**：工具实际执行的逻辑。需要编写代码，属于开发者功能，接口说明见[编排器工具 API](/zh-CN/development/extension-api/orchestrator-tools)。
- **模拟结果**：可选。为写入工具提供一份不修改真实状态的模拟返回，让迭代工作台在评审时看到接近真实的结构。

只读工具在模拟评审中真实执行。写入工具提供模拟结果时执行模拟版本，未提供时返回占位结果并标记为未验证。

## 启用与禁用

编排编辑器的自定义工具面板控制每个工具在本编排中是否提供给 Agent。取消勾选保留定义，之后可以重新启用。

节点、工作 Agent 或子代理可以单独覆写工具开关。单节点的覆写优先于编排默认值。

## 安全

工具的执行内容在页面环境中运行，权限与 Luker 自身模块相同：可以发起网络请求、修改全局状态、读取聊天内容。只使用你信任的代码。

导入带有自定义工具的角色卡时，Luker 先列出每个工具的名称、描述、模式与完整代码，再询问是否导入。可以全部接收、只导入角色卡而不启用工具，或展开逐项检查。

## 用 AI 修改工具

[AI 迭代工作台](/zh-CN/features/orchestrator/iteration-studio)可以读取现有工具、检查运行环境、在沙箱中试运行，并把新增或修改作为待审卡片提交。批准前不会写入编排配置。

来自其他扩展的工具定义不能在工作台里修改，只能切换启用状态；要改定义，需要回到注册它的扩展。
