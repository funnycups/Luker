# 状态系统

角色卡、聊天和预设可以保存自定义状态。CardApp 用它记录好感度、任务进度和物品清单，扩展用它保存每段聊天的数据，不必改写角色卡或聊天记录。

状态按命名空间隔离：每个扩展或 CardApp 读写自己的数据，互不干扰。状态在第一次写入时创建，随所属对象一起重命名或删除，服务重启后保留。

```d2
direction: right

OBJ: "角色卡、聊天、预设" {
  MAIN: "对象自身的数据" {
    style.fill: "#e1f5ff"
  }
  NS1: "命名空间 A\n某个扩展的状态"
  NS2: "命名空间 B\n某个 CardApp 的状态"
}

READ: "扩展只读写自己的命名空间"
LIFE: "对象重命名或删除时\n状态随之移动或删除"

OBJ -> READ
OBJ -> LIFE
```

## 三种状态

| 类型 | 跟着谁 | 常见用途 |
|---|---|---|
| 角色状态 | 角色卡 | 记忆摘要、游戏进度 |
| 聊天状态 | 聊天 | 生成确认、扩展的每聊天数据 |
| 预设状态 | 预设 | 预设级配置或运行时数据 |

预设状态由 Luker 管理存储布局。不要手动移动或编辑状态文件，以免与当前版本的结构不一致。

## 楼层状态

普通聊天状态每次整体覆写。楼层状态会记录写入发生在哪一楼、哪个 swipe。删除消息、编辑消息或切换 swipe 时，Luker 回放有效的提交，让插件状态跟随当前分支。
